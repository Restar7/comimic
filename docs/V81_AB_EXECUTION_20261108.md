## 2. P2：Recovery 改成"分项 Worst-Window 风险聚合"

`diff_vla_wbc/tracking_recovery_tail.py` 新增（**默认关，C 线行为不变**）：

```python
h_{i,t,k} = Huber_1( relu(z_{i,t,k} − z0_k) )
a_{i,k}        = TopMean_{25% tick}( γ^t · survival_t · h_{i,t,k} )
R_{k,tail}     = TopMean_{10% window}( a_{i,k} )
L_k            = w_k · [ 0.5 · mean_{i,t}(γ^t s h) + 0.5 · R_{k,tail} ]
L_R            = Σ_k L_k
```

**为什么这样**：旧口径是 `mean_{i,t}`，256 个样本里少数灾难窗口被稀释；现在每个 kernel
**各自**在窗口内取最差 25% tick、再在 batch 内取最差 10% 窗口，**风险项占一半权重**。

实测效果（同一 batch）：

| | 旧 `mean` | **新 `worst_window`** |
|---|---|---|
| `rec_root_ori_body` | — | 0.057 |
| `rec_root_ori_worst_tail` | — | **0.81** |
| **tail / body** | 1 | **≈14×** |

**z0 重标定**（V8.1 §3.4：困难 Train 分布 Q0.70）：

| kernel | 旧 z0 | **新 z0(Q0.70)** | 激活率 |
|---|---|---|---|
| root_pos | 0.645 | **0.175** | 31.5% |
| root_ori | **2.510** | **0.270** | 30.7% |
| body_linvel | 1.456 | 0.424 | ~30% |
| body_angvel | 3.142 | 0.519 | ~30% |

⇒ `root_ori` 的阈值降了 **9.3 倍**，激活率 1.9% → **30.7%**，落在 reviewer 要求的 20–40% 区间。
