## 1. 按评审意见修正上一版的四处过度解读

| # | 上一版的说法 | 为什么是过度解读 | 修正后的说法 |
|---|---|---|---|
| **1** | `cos≈0.1` 说明"只利用了 10% 的梯度" | 测的是 **`cos(Z_θt − Z_base, ∇_Z J20|Z_θt)`**：左边是 **Base→当前的累计位移**，右边是 **当前点的局部梯度**。这不是"训练器每一步往哪走"的指标 | 只能说：**最终累计位移与最终局部梯度的余弦约 0.1** |
| **2** | "理论上还能获得 11.6 倍收益" | 那是 **token 空间无约束的一阶上界**（`|g||Δ|`），LoRA 只能沿着它能到达的子空间走，不可能实现 | 改为：**一阶上界是 12 倍，但它是不可达的上界**，只用来衡量"方向差距"的数量级 |
| **3** | "物理 Loss 占用了约 52% 的梯度预算" | **梯度范数不能直接相加成比例**（要考虑方向与符号）。而且 `cos(∇L_added, ∇J) = −0.371` 也**不意味着**它阻碍 J：训练最小化 `L_added`，实际更新方向是 `−∇L_added`，反而与 `∇J` **正相关** | 改为：物理项与 J 的梯度**同量级**（范数 0.108 vs 0.096），**方向关系需要逐项测**；上一版对 `L_added` 的解读是错的 |
| **4** | "已经确定是 Situation C" | 还没验证最终 Actor 在**真实 Isaac** 的 20 步表现 | 改为：**仍在 A/C 之间**，需要 Isaac H20 对照（§7） |

**并且明确承认：低余弦本身不能证明 LoRA 有结构性瓶颈。**
本次单步实验就是为了直接测"每一次真实更新到底有没有用"。

## 2. 实验设计（可复现）

### 2.1 怎么得到"一次真实更新"【FACT】

```
① 复制 checkpoint_lora_0250.pt → actor_wm0_p2p4/checkpoint_lora_last.pt
   （trainer_state.pt 记录 update=250，二者一致）
② 用原配方的完整 argv（从 config.json 的 argv 取）resume 一步：
   --resume <run> --updates 251 --strict-resume 0
   （其余超参与原训练完全相同：lr=1.334e-5（cosine 到 400）、batch 32、7 项 loss、同样的 λ 与标定文件）
③ 训练器产出 stepprobe_0251/checkpoint_lora_last.pt = **θ_{t+1}**
```

该步的真实日志：

| 项 | 值 |
|---|---|
| update | **251** |
| lr | **1.334e-5** |
| loss | −1.3152 |
| J（训练 batch） | 1.4198 |
| grad_norm | 0.462 |
| 耗时 | 9.11 s/step |

### 2.2 怎么测方向【FACT】

脚本：`scripts/probe_step_update.py`
（固定 test 96 窗口 + 固定 flow 噪声 `seed=777`，θ250 与 θ251 用**同一个 seed**）

```
Z_t    = VLA(θ250, window, noise)        # 同噪声
Z_next = VLA(θ251, window, noise)        # 同噪声 ⇒ δZ 只来自参数变化
g      = ∂J20/∂Z |_{Z_t}                 # 在 θ250 的 token 处反传
cos    = <δZ, g> / (|δZ||g|)
ΔJ     = J20(Z_next) − J20(Z_t)
ΔJ_lin = g·δZ
ΔJ_opt = |g||δZ|                         # 同幅度沿梯度的一阶上界
```

产物：`runs/three_track_v8/c_tracking_recovery/step_probe_0251/step_test.json`

## 3. 结果

| 指标 | mean | median | 分布 |
|---|---|---|---|
| **cos(δZ, g)** 全 40×64 | **+0.0604** | +0.0514 | std 0.097；min −0.197 / max 0.266；**76.0% 为正** |
| **cos(δZ, g)** 前 20 帧 | **+0.0809** | +0.0707 | std 0.135；min −0.351 / max 0.347；**76.0% 为正** |
| **ΔJ = J20(θ+1) − J20(θ)** | **+9.456e-5** | +5.811e-5 | std 2.05e-4；min −2.59e-4 / max 1.61e-3；**73/96 = 76.0% 为正** |
| ΔJ_lin = g·δZ | +9.494e-5 | +5.728e-5 | 与 ΔJ **几乎逐位一致** ⇒ 处在线性区 |
| ΔJ_opt = \|g\|\|δZ\| | **+1.156e-3** | +8.68e-4 | **是实际的 12.2 倍** |
| \|δZ\| / \|Z\| / \|g\| | 0.00324 / 8.273 / 0.5048 | — | 单步位移只占 token 范数的 **0.04%** |

**训练器自测（它的口径）**：`J 1.592134 → 1.592229`（**+9.4e-5**，与探针的 +9.456e-5 一致）。

## 4. 这说明了什么

### 4.1 训练没有坏：【FACT】

* 单步更新让 **76%** 的窗口 J20 **上升**，合计 **+0.00908**；
* `ΔJ_lin ≈ ΔJ`（9.494e-5 vs 9.456e-5，相对差 **0.4%**）⇒ 更新处在**线性区**，测量的 ΔJ 可信；
* 所以"LoRA 参数化坏了 / 梯度传不进去"这类结构性假设**不被支持**。

### 4.2 但方向效率确实低：【INFER】

* `cos(δZ, g) ≈ 0.08`；
* 同幅度沿梯度走的一阶上界是 **12.2 倍**（不可达，但说明方向差距的量级）；
* 单步只有 **0.04%** 的 token 位移，说明现在**靠大量小步累积**在拿收益；
* 与累计位移的 cos（it=50–250 的 0.096–0.119）**一致** ⇒ 低 cos **不是"训练后期越训越偏"**，
  而是**每一步本来就这样**。

### 4.3 低 cos 的来源（都可测）【GUESS】

| 来源 | 说明 | 怎么测 |
|---|---|---|
| **Adam 预条件** | 更新是 `−lr·m̂/(√v̂+ε)`，逐元素被 `1/√v̂` 重加权，天然偏离原始梯度 | 用 SGD（关 Adam）跑一步比 cos |
| **物理项** | 物理项与 J 的有效梯度同量级（0.108 vs 0.096），合成方向是折中 | **关物理项跑一步**，看 cos 与 ΔJ |
| **多窗口共享参数** | 一个 batch 里窗口的目标可能互相冲突（不同 clip/任务），梯度平均后方向变钝 | 单窗口 batch 跑一步比 cos |
| **低秩约束** | rank16×218 层的可达子空间未必含 g（**尚未验证**） | 只训 proj_out / rank 16→64 |

> **评审的提醒成立**：这些都不是"错误"，是正常的复合优化现象。真正要回答的是
> **"这种低效的更新，在真实 Isaac 里是否仍然改善 20 步 tracking"**——§7。

## 7. 还缺的那个实验（评审 #3，也是我们现在唯一的定性手段）

**真实 Isaac H20 对照（C vs Base）**：

* 选 **24 个**可完整恢复物理状态的窗口，优先覆盖 OpenDoor / SitSofa / VisionNavi；
  按任务阶段与 `cos` 高低分层（不要只抽容易窗口）；
* 同一初始状态、同一参考、同一随机性协议，分别执行 **Base 与 C**；
* 计算同一口径的：

```
ΔJ_WM    = J_WM(C)    − J_WM(Base)
ΔJ_Isaac = J_Isaac(C) − J_Isaac(Base)      # 真仿真状态 + 同一参考，H=20 tracking
```

判读：

| 结果 | 含义 | 下一步 |
|---|---|---|
| ΔJ_WM>0 且 ΔJ_Isaac>0 | 短程有效闭环 | 不再怀疑 WM；转向"局部→长期任务"的传导 |
| ΔJ_WM>0 但 ΔJ_Isaac<0 | WM 在 Actor 实际动作上预测有偏 | 诊断 WM 在 Actor 动作分布上的误差 |
| ΔJ_WM≈0 且 ΔJ_Isaac≈0 | 更新对该窗口无影响 | 查窗口/阶段覆盖 |

## 9. 给评审的 6 个问题

1. **+9.5e-5 / 步 的量级合理吗？** 训练 280 步总 ΔJ 是 +0.0164，但单步是 +9.5e-5（若线性应得 +0.027）。
   这个"步数换收益的边际递减"是正常的饱和，还是说明后期步数被浪费？
2. **cos≈0.08 的归因顺序**：你会先做"关物理项跑一步"还是"改用 SGD 跑一步"来分离
   Adam 预条件 vs 复合损失的贡献？为什么？
3. **24 个 Isaac 窗口怎么选**：按任务/阶段/`cos` 分层，具体你会怎么分配这 24 个名额？
4. **单步探针的可信度**：`ΔJ_lin ≈ ΔJ` 说明处在线性区。这会不会让"12.2× 上界"看起来比实际更乐观
   （因为一旦沿梯度走远就会饱和）？你会怎么给这个上界打折？
5. **resume 指纹 FAIL**：这是采样流复现的问题。在只有 1 个 seed、且 resume 不可靠的情况下，
   你会怎么设计下一轮"可复现"的训练？（固定 batch 索引？固定 sampler 状态？）
6. **如果 Isaac H20 显示 ΔJ_Isaac<0**：你会先怀疑 WM 的动作响应（增益/接触），
   还是先怀疑"Actor 动作分布超出 A′ 的动作覆盖"？两者的判别实验分别是什么？
