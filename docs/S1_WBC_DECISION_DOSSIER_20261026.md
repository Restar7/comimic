## 2. 必须先看懂的口径（否则所有数字都会读反）

### 2.1 HA 录制里有两套关节，token 来自"指令"那套

`data/ha_raw/<task>/tw/*.npz` 里同时存着（实测 clip `…_sonic_1776268633456387`，2080 帧）：

| 字段 | 含义 | 与 `data/npz/ha_tokens` 的 `joint_pos` 关系 |
|---|---|---|
| `encoder_motion_joint_pos_hist (2080,46,29)` | **命令流**：每帧下发给控制器的关节目标 | mean\|Δ\| = **0.109 rad** |
| `robot_qpos_before_decimation (2080,29)` | **执行轨迹**：机器人真正到位后的关节角 | mean\|Δ\| = **0.00000**（逐位相等） |
| `encoder_latent (2080,64)` | 64 维 token | = `npz.g1_motion_token_64`（**逐位相等**） |

结论：**64 维 token 是用"命令流"算出来的**，而 `data/npz/ha_tokens` 的 `joint_pos` 是"执行轨迹"。
两者差 0.109 rad（全库 0.29–0.34 rad），最佳 lag **+8 帧 = 0.16 s**（机器人跟指令的延迟）。

## 4. 分析（每条都有 §3 的数据支撑）

### 4.1 两张表方向相反 —— 是口径，不是能力

| 臂 | 新表（命令流） | 旧表（执行轨迹） |
|---|---|---|
| A | 0.8203 → 0.8604 → **0.8673**（**+0.047**） | 0.7094 → 0.6272 → **0.6178**（**−0.092**） |
| B | 0.8166 → 0.8636 → **0.8675**（**+0.051**） | 0.5156 → 0.5269 → **0.5341**（+0.019） |

同一批训练，**新表上两条臂都涨 +0.047~0.051；旧表上 A 掉 0.092**。
原因是训练库的 HA 片段是命令流口径（已验与新表逐位一致），训练必然把策略往命令流拉、离开执行轨迹口径。
→ "某个 ckpt 在旧表分高"常常只说明它**训得少**（A@16120 就是旧表最高分，但它新表最差、BONES 也最差）。

### 4.2 旧表 NR 一路下降，63% 是 `body_orientation`

A 系 16120 → 20000 的降幅 −0.0916 拆分：body_orientation **−0.0579（63%）**、body_angvel −0.0120（13%）、
body_linvel −0.0085（9%）、body_pos −0.0059（6%）、root_pos −0.0043（5%）、root_ori −0.0029（3%），
两项惩罚还变好了。物理量：**朝向 12.9° → 20.9°**（位置只从 7.1 → 8.9 cm）。

机理解释：朝向核 `exp(−θ²/0.16)` 在 θ≈0.2 rad 处最陡（13°→21° 就吃掉 40% 项值），
而位置核 `exp(−d²/0.09)` 在 7–10 cm 仍很平 → **"参考朝向上 0.34 rad 的口径差"全部记在 orientation 这一栏**。

### 4.5 WM 标定被 S1 训练摧毁（本档案最重要的发现之一）

`qd_corr`：10500 起点 **0.737** → A@16120 0.142 → A@20000 0.111 → B@14800 0.090。
`joint_mse`：5e-5 → 3.6e-3（**70 倍**）。而 `--state-vel-weight` 的注释里也写着
"Isaac WM 想象出的速度与参考速度相关仅 0.077"——与 0.09–0.14 完全对得上。

**机理**：WM 是在 replay buffer 上跟策略一起训的；S1 把策略拉向命令流口径后，
WM 学到的是"新策略 + 混合库"的转移分布，而评测用 label token 域下的策略动作 → 速度通道掉到近乎无关。

**补救（已实测）**：把 10500 的 `wm` 拼到新策略上
（两者 `wm_integration` 都是 `explicit_dt0.02`、state dict keys 完全一致）：
`qd_corr 0.111 → **0.702**`、`ratio 3.10 → **1.00**`、`joint_mse 3.8e-3 → **7e-5**`、`rollout reward 0.0720 → 0.0763`。
→ 若联合微调依赖 WM 想象（`imag_return_norm_vla` 等），**C1/C4 明显优于 C2/C3**。

### 4.6 B 为什么差这么多（起点欠账占八成）

B vs A@18500 的总差 0.1003 拆解：body_linvel +0.0300（30%）、body_orientation +0.0267（27%）、
body_angvel +0.0220（22%）、root_ori +0.0075、body_pos +0.0061、root_pos +0.0040（B 在惩罚项上还略好）。

而"起点差"（A@16120 vs 10500）= **0.1938**，其中 body_orientation **+0.0782（40%）**、linvel +0.0414（21%）、
angvel +0.0391（20%）—— 也就是说 **B 缺的正是 10500 → 16120 那 5500 iter 买到的"朝向 + 速度"**，
B 后续 4200 iter 只补回约一半（+0.019），且朝向基本没动（0.0671 → 0.0647）。
即：**朝向那一项靠继续训补不动**，它由"参考口径"决定。

## 9. 附录：WM 速度通道怎么"修"（已闭环，2026-10-26 09:00–09:06）

### 9.1 当时的"修法"

不是"多训几轮"，而是两个东西：

1. **结构修复**：把 WM 的整步残差增量换成 mjlab 的半隐式**显式积分**（`wm_integration=explicit_dt0.02`）。
   对应文件 `ckpt_010500_physint*.pt` 那一串（`physint` / `physint_fix` / 再转 obs93 / 再 spec）。
   `runner.py` 也有对应说明："带 ``wm_integration`` 的（如 ckpt_*_physint.pt）→ mjlab 的半隐式显式积分"。
2. **专职标定**：`scripts/finetune_wm_velocity_policy.py` —— 用**策略自己的动作**当 WM 输入，
   只对速度通道加权（`--vel-lambda 5.0`），位置项当正则；800 步、lr 3e-4、batch 256、
   数据用 `data/npz/ha_tokens` + `runs/isaac_motion/ha_tokens/packed.pt`（**与评测同域、同 label token**）。
   脚本里的验收标准写得很明白：*"WM 的 qd 相关必须 > 0.9（was 0.155）"*。

### 9.2 走错的一条路（已失败，留档）

先试了复用 RL 训练器的 WM-only 模式（`WM_ONLY_ITERS=999999` → policy 恒 0 更新，只训 WM，
500 iter，`LIBRARY=runs/isaac_motion/ha_tokens/packed.pt`）：

| 迭代 | 训练内 `wm_loss` | 评测 `qd_corr` |
|---|---|---|
| 20000（原样） | 0.0315 | 0.1114 |

| +200 | 0.0593 | 0.0984 |

**教训**：RL 训练器优化的是"WM 在自己采样分布上的一步误差"，而 `qd_corr` 量的是
