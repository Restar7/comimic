## 0. 一页结论（给评审先看这段）

**BPTT 的计算图和解析梯度是对的**（有限差分相对误差 1.7%，梯度确实穿过 SONIC decoder 回到 token）。
**纯 BPTT 也确实能把 WM 回报抬起来**——但抬起来的那部分基本是**一个共享常向量**：

| 设置（256 个训练窗口，held-out 按 clip 分组） | Train ΔJ | Val ΔJ | Test ΔJ |
|---|---|---|---|
| Constant（64 维共享向量，BPTT 学） | **+0.0162**（+1.08%） | **+0.0156**（+1.04%） | **+0.0118**（+0.81%） |
| State MLP（`f(token0, state64)`，1.25M 参数） | **+0.0700**（+4.67%） | +0.0114（+0.76%） | +0.0044（+0.30%） |
| MLP − Constant（逐窗口配对） | — | — | **−0.0058 ± 0.0023**（t≈−2.5） |

⇒ **MLP 在训练集上比常向量好 4.3 倍，在 held-out 上比常向量差 42%。**
决定性负对照：把 `state64` **跨窗口打乱**、甚至**整块置零**，MLP 的训练回报几乎不变
（+0.0730 / +0.0644 vs 真 state 的 +0.0700）。也就是说，**训练集上的增益不是状态相关的那部分带来的**。

机制层面（实验 4）：逐窗口共享修正梯度 `gᵢ = ∂Jᵢ/∂Δᵢ` 的
`rms(残差)/‖mean g‖ = 5.75`（最优点确实不是常数），
但**两两余弦只有 +0.043（48% 为负）**，且用 `(token0, state64)` 做**按 clip 分组的 CV** 预测 `gᵢ`
的 held-out 余弦只有 **0.11~0.16、R² 全为负**。
⇒ **状态相关的梯度信号客观上就很弱、且几乎不可由现有输入预测**，不是"优化器没学会"。

## 2. 本次实验的最小化设计（与原训练脚本的关键差别）

为了把"能不能学"和"loss/正则/辅助项"分开，本轮**只保留一个目标**：

```
L = -mean_i J_i ,      J_i = Σ_{t<H} γ^t r_t   （H=20, γ=0.99, survival≡1）
token'_t = token_t + cap(Δ_i) ,  Δ_i = f(token_0, state64_i)
```

关闭：critic / imagined bootstrap / window_norm / grad-target 辅损 / 反常量正则 / LoRA /
观测噪声 / push 扰动 / λ 小扰动约束（λ=0，改用**软范数上限**约束幅度）。

| 项 | 取值 | 说明 |
|---|---|---|
| 数据 | `runs/a_prime_sonic_exc/all_transitions.pt`（529,131 条真 Isaac 转移） | 起点只取"真采到过"且漂移 ≤0.10 m 的帧（346,729 帧） |
| 窗口 | 448 个：train/val/test = **256/96/96** | **按 clip 分组**抽样，clip 数 375/81/81，任务覆盖各 6 类 |
| 起点 | `recorded_states` + 10 步 burn-in（与 bptt1 同一条 `sample_burnin`） | 参考帧、`history`、`xi`、`prev_action` 全部由这一段产生 |
| token chunk | **官方 VLA（checkpoint-8000）在窗口自己那帧上采样并缓存**（fm_steps=4） | 两次独立采样做方差诊断；也缓存了录制库 token 用于对照 |
| WM | `runs/a_prime_sonic_exc/wm_gain2.pt`（冻结） | sha256 `fc5aeb30e987…` |
| 执行器 | SONIC release decoder（ONNX→torch 图，可微） | 与部署同一个 decoder |
| 奖励 | `apply_reward_cfg` 读 `runs/bptt1/args.json`：`saturating, vel_scale=1, huber 0.02/0.15, d_max=0.3, root_ori=split, tail_w=2, yaw_hinge=0.3, term_off=1` | 与 bptt1 逐项相同 |
| 幅度预算 | `apply_norm_cap(Δ, 0.08)`（tanh 软上限，**与部署同一个函数**） | 0.08 = η（=0.15/1.8 的部署口径） |
| 优化 | 全批量 Adam，80 步；lr ∈ {1e-3, 3e-3, 1e-2}（**两臂同一候选集**） | 无 checkpoint 选择、不碰测试集调参 |

**数据侧的两个硬事实**（会影响可学性上限）：

- `‖token_0‖ ≈ 1.337`；VLA token 与录制库 token 的平均绝对差 **0.0717** ——
  与整个 Δ 预算 0.08 同量级；
- VLA **自身两次采样**的平均绝对差 **0.0328（相对 24.1%）** ——
  即"我们想学的状态相关修正"里，有相当一部分会被 VLA 自己的采样噪声淹没。

## 6. 实验 4：为什么"塌成常向量"？——逐窗口梯度结构

`gᵢ = ∂Jᵢ/∂Δᵢ`（Δ 广播到整段 chunk，逐窗口独立求导；**不是**旧的单 token Teacher 口径）：

| split | n | ‖gᵢ‖ | ‖mean g‖ | rms(res) | res/mean(L2) | 两两 cos 均值 | cos<0 占比 |
|---|---|---|---|---|---|---|---|
| train | 256 | 1.127 | 0.193 | 0.192 | **5.75** | **+0.043** | **48%** |
| val | 96 | 1.087 | 0.247 | 0.184 | 4.31 | +0.054 | 46% |
| test | 96 | 1.250 | 0.317 | 0.226 | 3.84 | +0.066 | 44% |

**特征 → gᵢ 的分组 CV（按 clip 分组，held-out；ridge 与 2×256 MLP）**：

| 特征 | 模型 | R² | cos(预测, 真值) | 逐元素 corr |
|---|---|---|---|---|
| token only | ridge | −0.423 | +0.128 | +0.083 |
| token only | MLP | −1.052 | +0.135 | +0.071 |
| state only | ridge | −0.856 | +0.141 | +0.072 |
| state only | MLP | −1.070 | **+0.160** | +0.066 |
| token+state | ridge | −2.243 | +0.108 | +0.052 |
| token+state | MLP | −0.726 | +0.144 | +0.089 |
| token+state → 残差 | ridge | −2.243 | +0.085 | +0.042 |

读法：**最优点确实不是常数**（res/mean=5.75，比旧文档的 2.835 还强），
但**它不可由现有输入预测**（held-out cos 0.11~0.16、R² 全负）。
"跨窗口求和会把方向平均掉"这个说法**不完整**：参数梯度里含"特征 ⊗ 逐窗口梯度"的相关项，
只有当**特征与梯度的相关性**接近 0 时才会退化成裸平均——上表正是这个相关性的直接测量，
结论是**它确实接近 0**（cos ≈ 0.1，R² < 0）。

## 9. 严格判决

### A. BPTT 计算图是否正确？ → **PASS**
参数进图、进 optimizer、梯度有限非零、权重真的更新、`dJ/dtoken0≠0`、解析梯度与中心差分一致
（1.7%，小 h 的偏差归因于 float32 舍入）。

### B. BPTT 能否优化固定窗口的 WM 回报？ → **PASS（但天花板低）**
Constant 在 32/256 窗口上都把 ΔJ 抬到 +0.016~+0.028（约 +1.1~1.9%），lr 三档稳定；
MLP 在训练窗口上更高（n=256：+0.070，+4.7%）。代价是 ‖Δ‖ 顶到部署预算 0.08，
再放大预算（0.16/∞）**并不提高** ΔJ，只让动作 RMS 从 0.023 涨到 0.05+。

### C. BPTT 的 MLP 能否超过 Constant？
- **训练集：能**（n=256：+0.0700 vs +0.0162，4.3×）。
- **held-out：不能**（val +0.0114 vs +0.0156；test +0.0044 vs +0.0118；
  逐窗口配对差 **−0.0058 ± 0.0023**）。

### D. 状态相关性是否有真实回报价值？ → **在本数据上：无证据**
三个独立判据同向：① 打乱/置零 state 不掉分；② gᵢ 的 held-out 可预测性 cos≈0.1、R²<0；
③ 两两 cos≈0.04。**不建议**再用 `state_sens`/输出方差作为"学到了状态"的证据。

### E. 之前 BPTT 失败最可能属于哪类问题？ → **常量捷径 + 泛化不足（不是梯度路径）**
并且更根本的一层是：**目标里可学的状态相关信号太弱**（Exp4）。
`teacher 不对齐`/`decoder-WM mismatch` 在本轮**已被排除**（本轮不用 teacher、decoder 与部署同一个）。

## 10. 任务书 §15 的五个问题（当前证据下的回答）

1. **纯 BPTT 到底能不能提高 WM reward？**
   能，但很有限：held-out +0.0137（≈+1%），且必须把 ‖Δ‖ 顶满 0.08。

2. **它能不能学到比常向量更有效的状态相关修正？**
   训练集能（+4.3×），held-out 不能（−42%）。所有 held-out 比较里 MLP 都没赢过 Constant。

3. **如果能在训练集学，为什么在 held-out 上失败？**
   (a) 每窗口最优方向两两正交（cos≈0.04），共享参数只能学均值；
   (b) 残差与输入特征的 held-out 相关性只有 0.1~0.16；
   (c) 1.25M 参数在 32~256 个窗口上首先拟合的是**每窗口记忆**（打乱 state 不掉分即证据）。

4. **现在有没有足够证据继续投入 BPTT？**
   **没有足够证据支持"继续在'共享 Δ + 20 步 WM 回报'上加大投入"。**
   可以继续，但前提是先改**目标/输入**，而不是调优化器或加正则。

5. **下一步最值得做的三个实验**（按性价比排序）
   1. **输入补 `state − ref`（跟踪误差）**：Exp4 显示 ĝ 与"离参考多远"强相关，而当前 state64 里没有 ref。
      这是唯一一个"信息层面"的可能缺口，成本 ~20 行。
   2. **换教师目标**：把 20 步 WM 回报换成"逐窗口 ∂J/∂Δ 的**蒸馏**"（会话 02 的路线 B），
      它不做跨窗口求和；本轮的 Exp4 CV（cos≈0.15）给出了这条路的**上限预估**——
      注意上限也很低，先算清期望再投入。
   3. **真物理小样本裁决**（会话 04）：Constant vs MLP 在 Isaac 里各跑 N 个窗口的 ±δ 真回报，
      直接回答"WM 里 +1% 到真机还剩多少"。这一条决定前两条是否值得做。

## 11. 限制与最重要的不确定性

1. **只有 WM 回报，没有真机**：H=20 的 WM ΔJ 已知高估约 1.8×（前人实测）。
2. **token chunk 是一次采样并缓存的**（fm_steps=4）；VLA 自身采样噪声（相对 24.1%）
   与 Δ 预算 0.08 同量级 ⇒ 一部分"状态相关修正"会被采样噪声淹没。
3. **每臂只训 80 步全批量 Adam**（32/256 窗口），不是训到收敛。但 Constant 在 lr 三档、
   三 seed 上稳定，MLP 在训练集已明显高于 Constant（不是欠训），趋势可信；
   **缺逐 epoch 的 held-out 曲线**，所以"过拟合"是从端点 train/held-out 差距 + 消融推断的。
4. **最大的不确定性**：Constant 在 held-out 上 +1% 的增益，有多少是 WM 的**系统性癖好**
   （BPTT 学到的是 WM 的偏差而不是真机的好处）。本报告无法回答 —— 必须由会话 04 裁决。
