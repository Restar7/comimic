### 1.1 续训起点：从哪个 ckpt 续、权重动没动

**一句话：从 mjlab/MuJoCo 那条线的 BONES-SEED 底模
`logs/e9_bones_seed_token_h200x2/ckpt_0024000.pt`（24,000 个 env step）出发，
经一次预处理把 bin 采样表换成 318 库的，得到 `runs/wbc_resume/e9_0024000_ft318.pt`。**

```
源：   third_party/SuperMimic-Reproduced/logs/e9_bones_seed_token_h200x2/ckpt_0024000.pt
         iteration = 24,000 / num_updates = 9,584 / bins = 1,013,724 / token_dim = 64 / obs 93
   ↓   scripts/prepare_wbc_resume.py   （只因为参考库换了 318，bin 表尺寸必须重写）
用：   runs/wbc_resume/e9_0024000_ft318.pt
         iteration = 0 / num_updates = 0 / bins = 9,625 / config.data.{library,tokens} 指向 318
```

**逐张量比对（本机实测，不是声明）**：

| 项 | 源 → 预处理后 |
|---|---|
| `policy`（22 张量） | **完全一致**（`torch.equal` 全 True） |
| `wm`（15 张量） | **完全一致** |
| `critic`（7 张量） | **完全一致** |
| `wm_opt` / `policy_opt` / `critic_opt`（18.6M+9.6M+0.47M 个状态） | **完全一致** |
| `bin_return` / `bin_memory` | 1,013,724 → **9,625**（按 318 库重建） |
| `iteration` / `num_updates` | 24,000 / 9,584 → **0 / 0** |

⇒ "续训 20k" 的准确含义：**权重从 e9 第 24,000 步的状态出发，在 318 参考库上再跑 20,000 个
env step**；新 run 的 `iteration` 从 0 数到 20,000（所以 `--schedule.total-iterations 20000`）。

**为什么选 24k 这一份**：

| 理由 | 依据 |
|---|---|
| 318 时代那次联合微调（`runs/joint_sm24k_hand`）用的底模就是它 | `docs/FT318_HAND_JOINT_1000_20261025.md:15`（run 名里的 `sm24k`） |
| 早于后来 Isaac 侧的显式积分/速度通道那批改动，口径干净 | e9 的 `config.json` 里 `explicit_integration=true` 是 mjlab 原生行为 |
| 同目录更强的是 `ckpt_0156000.pt`（156k 步）/ `ckpt_latest.pt` | 没在 318 口径上验证过，先不混（换法见下） |

**想换起点**（同样必须先预处理，因为它们也是 1,013,724 bins）：

```bash

### 3.1 参数逐条说明（照抄时别改这几项）

| 参数 | 值 | 为什么 |
|---|---|---|
| `--data.tokens` | `ft318_tokens.pt` | 条件 token 用数据集真值（§5.2）；不加就是在线重建（不准，见 §6.2） |
| `--resume` | `e9_0024000_ft318.pt` | 必须是**预处理过**的那份；原 e9 ckpt 的 bin 表是 1,013,724，会崩 |
| `--policy.token-dim 64` | 64 | 必须与 ckpt 一致；decoder 首层因此是 `64+930=994` |
| `--schedule.total-iterations 20000` | 20k | `iteration` 已被预处理归零 ⇒ 这就是"续训 20k" |
| `--schedule.checkpoint-interval 1000` | 1000 | 20 个 ckpt × 183 MB ≈ 3.7 GB；便于挑 |
| `--env.num-envs 4096` | 4096/卡 | 与 e8/e9 同配置，峰值 ~22 GB/卡（H200 141 GB，宽裕） |
| `--env.no-reset-noise` | 关姿态扰动 | 录制 token 的 anchor 绑定录制姿态，开了会不自洽（§6.2 / R13）；想量代价就加一条不加此开关的对照臂 |
| `--wm-trainer.lr 1.4e-5` + `--policy-trainer.lr 1.4e-5` | 有效 2e-5 | `Trainer` 在 world=2 时把 lr 乘 √2（`training/loop.py:41-44`） |
| `--wm-trainer.batch-size 2048 --batches-per-update 10` | 同 e9 | WM 每次更新吃 10×2048 条 8 步真转移 |
| `MUJOCO_GL=disable` | — | 无渲染，避免 EGL 依赖 |

## 6. 跑完验收（4 条，任一不过就别往下接 J1）

```bash

      '| bins', int(ck['bin_return'].numel()), '| token_dim', ck['config']['policy']['token_dim'])

         task_3_kitchen_plate_milk_transfer task_4_diningroom_can_low_chair; do

    --ckpt "$CKPT" --npz-dir $COMIMIC/data/npz/g1_tasks --clips $CLIPS \
    --num-envs 8 --device cuda:0 --out $COMIMIC/runs/w1_eval_ft318/bench_$T.json

| W1-2 | 同 W1-1，但 `--tokens` 指向打乱的 token 表 | 相对下降 ≥ 30% |
| W1-3 | 四任务各 8 条 | 每任务 `mean norm return` ≥ 底模 × 0.95 |
| W1-4 | 上面的 python 自检 | 无 NaN、`bins==9625`、`iteration` 单调 |

## 8. 常见报错

| 报错 | 原因 | 处置 |
|---|---|---|
| `size mismatch ... bin_return` | 用了未预处理的 e9 原 ckpt | 跑 `scripts/prepare_wbc_resume.py` |
| `unrecognized arguments: --data.tokens` | upstream patch 没生效 | 确认 `config.py` 有 `tokens` 字段、`loop.py` 有分流分支 |
| `[sonic] token conditioning enabled (dim=64)` | 走了在线构建器（说明 `--data.tokens` 没传或路径错） | 检查路径；期望日志是 `[tokens] recorded dataset tokens ...` |
| `FileNotFoundError: SONIC encoder ONNX` | 用了在线构建器 | 同上；用录制 token 时不需要 encoder |
| `KeyError: 'bin_return'` | 续训的 ckpt 不是训练产物 | 换 `ckpt_*.pt`（`sm-train` 产出），不是联合微调的 `joint_*.pt` |
| `The size of tensor a (9625) must match ... (9621)` | bin 公式用错（`ceil((L-1)/50)` 而非 `ceil(L/50)`） | 用本仓库版本的 `prepare_wbc_resume.py` 重新生成续训 ckpt |
| 日志只有 `bash: --env.num-envs: command not found` | 手抄命令时把注释贴进了 `\` 续行 | 用 `bash scripts/launch_w1_ft318.sh`；或把行尾注释全删掉 |
| `CUDA out of memory` | `num_envs` 太大 | 降到 2048/卡（H200 一般不会） |
