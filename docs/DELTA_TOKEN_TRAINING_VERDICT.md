# Δtoken 训练口径判决（截至 2026-11-07）

> 目的：把"哪些是**测出来的**、哪些只是**WM 里的**、哪些**还没验证**"分开写清楚，
> 避免把 cos 之类的中间量与"闭环成功率"混为一谈。

---

## 1. 两种 Teacher 的定义差异（这是最容易踩的坑）

| | legacy Teacher | **规范 Teacher（shared_delta）** |
|---|---|---|
| token 输入 | 只用 `token_0` 反复重复 | **整段 chunk**（每步 `token_t`） |
| Δ 的形状 | 每步独立 ε | **共享 ε**（`token'_t = token_t + ε`） |
| J 的定义 | `rewards.sum()`（未折扣） | **`discounted_return(rollout, γ)`**（含 survival） |
| reward 视界 | 固定 H | `reward_steps = v3.reward_horizon`（0=满 H） |
| 代码 | `_teacher_cfg()` 里 `teacher="legacy"` | 默认 `grad_target_teacher=shared_delta`、`grad_target_reward=discounted` |
| 测试 | 仅用于历史复现 | `tests/test_teacher_shared_delta.py` |

**任何历史数字如果来自 legacy Teacher，都不能与 shared_delta 的数字直接比较。**

## 2. 已经**在真机（Isaac）里**验证的结论

做法：取真实窗口，用 WM 反传得 `ĝ = ∂J/∂A`，归一化到动作 RMS δ=0.03 rad，
在真物理里从同一起点执行 `a0 ± δĝ` 走 H 步，用**同一个 reward** 结算。

| 视界 | 窗口数 | 符号一致率 | **真物理变好比例** | ΔJ 相关 | J_true 均值 | J_WM 均值 |
|---|---|---|---|---|---|---|
| H=2 | 96 | 1.000 | **1.000** | +0.964 | +0.0076 | +0.0087 |
| H=20 | 64 | 0.984 | **0.984** | +0.092 | **+0.0587** | **+0.1277** |

⇒ **结论①（Isaac 已验证）**：WM 的**方向**可用（连 H=20 也可用）。
⇒ **结论②（Isaac 已验证）**：WM **高估幅度**：中位比 **1.79×**、均值比 **2.17×** ⇒ 部署 η 要打折。
⇒ 脚本：`scripts/probe_wm_gradient_truth.py plan|score` + `scripts/isaac_probe_action_rollout.py`
⇒ 日志：`logs/truth_probe.log`、`logs/truth_probe_h20.log`

⚠️ 注意口径：这是**动作空间 29 维的正负方向比较**，**不是**"token 空间 `J(+Δ) > J(Base)`"的证明；
后者属于 Gate B（**未跑**）。

## 3. 只在 **WM / 标签拟合**层面验证的结论（不代表真机收益）

### 3.1 可学性（特征 → ĝ 的余弦，n=3072，8 折 CV）

| 目标 | 特征 | ridge cos | MLP cos |
|---|---|---|---|
| `∂r₀/∂token`（1 步） | token | 0.194 | 0.175 |
| | state | 0.393 | 0.418 |
| | state+act0 | 0.472 | **0.500** |
| `∂J₂₀/∂token`（20 步） | token | 0.206 | 0.236 |
| | state+token | 0.232 | 0.334 |

⇒ **结论③（标签拟合层面）**：k=20 的可学性明显低于 k=1；这条决定了"标签视界"的选择。

### 3.2 离线蒸馏（纯监督，训练阶段不碰 WM/VLA）

| 标签数 | 切分 | held-out cos | 备注 |
|---|---|---|---|
| 3,072 | 随机 70/30 | 0.360 ± 0.006 | 偏乐观 |
| 3,072 | **按参考簇留出（10 折）** | **0.256 ± 0.034** | 跨运动口径 |
| 5,632 | 按参考簇留出 2 簇 | **0.403（η=0.08）/ 0.416（η=0.15）** | train cos 0.52~0.59 |

⇒ **结论④**：标签量是主要瓶颈（3k→5.6k 让跨簇 0.256→0.416，尚未收敛）。

⚠️ **口径作废提醒**：上面 5,632 那一行用的是**旧口径**（`port_tokens` 标签点、`sum` 目标、
离线器 rot6d 列优先）。这三处已在 2026-11-07 修正（`6526a99`/`63d6e0a`），
**该行数字只能当"量级参考"，不可作为对外结论**。

## 4. 已经**失败**的路线（有实测）

### 4.1 BPTT（端到端报酬反传进 Δ 参数）

| 轮次 | 参数化 | 结果 |
|---|---|---|
| v10/v11/v13 | LoRA | 学到常向量（跨臂 cos 0.95~0.997） |
| p1b/p1c/p1d | 反常量项 0.03/0.1/0.3 | `残差/均值` 0.164 / 0.170 / 0.081 ⇒ 仍是常数 |
| p1e | lr 5e-4、λ_r=15 | 探针 `‖Δa‖ = 4.83η`（过冲不可部署），`残差/均值` 0.105 |
| **bptt1**（2026-11-07） | λ_r=2.8 + 逐窗口归一化 + fullstate | 43 步：`rollout/reward` **+1.5%**，`act/rmse` **+98%** ⇒ **薅 WM** |

**机制解释**：参数梯度 ≈ `Σ_w g_w ⊗ φ(x_w)`，早期输出对所有窗口近似相同 ⇒ 一步跳到**平均方向**；
之后状态相关部分只剩小残差梯度。正则项只能强制"有方差"，不能强制"方差有用"（三个 VAR_WEIGHT 档位均失败）。

⇒ **结论⑥**：在本配置下"报酬反传"反复产生"过冲 + 常向量/薅 WM"，**不建议作为默认**。
（这不等于"数学上不可能"；会话 03 的诊断脚本保留用于进一步判定。）

### 4.2 为什么改用蒸馏

| | 报酬反传 | 蒸馏 |
|---|---|---|
| 参数梯度是否穿 WM | ✅ 穿（20 步 + 跨窗口求和） | ❌ 不穿（纯回归） |
| 幅度控制 | 靠 λ_r/act 惩罚平衡（易过冲） | 由标签 η 显式钉住 |
| 已验证结果 | 常向量/薅 WM | 留出 cos 0.4 量级、幅度合格 |

## 5. **尚未验证**的部分（不得声称）

1. **闭环成功率**：唯一一次 Δ 闭环（`runs/ab_d15k`）为 1×timeout（`max_reward=0`）+ 1×`Connection refused`，
   且**无视频、无逐步 dump** ⇒ **无效证据**。
2. **跨任务泛化**：标签来自运动库（走/跟踪），部署在 SitSofa / VisionNavi / OpenDoor / DoubleDesk
   ⇒ 分布差异从未测过。
3. **token 空间配对（Gate B）**：`J_isaac(+Δ) vs J_isaac(0)` 未测。
4. **解码器一致性**：Torch 复刻 vs ONNX 的历史对拍（~1.9e-6）需要在集成后复跑确认。
