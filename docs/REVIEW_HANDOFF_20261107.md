# Δtoken（教师标签蒸馏）项目评审材料（截至 2026-11-07）

> 目的：把**当前设计、全部关键参数、实测数字、失败机制、未验证项**一次讲清，供外部评审。
> 所有数字都标了来源文件/脚本；凡未测的都明确写"未测"。请据此判断，不要接受任何未标来源的说法。

---

## 0. 一句话现状

部署链路里有一个**冻结的 VLA** 输出 64 维 motion token，我们想训练一个**小头（Δtoken）**在 token 上加一个残差，
使闭环成功率提高。**教师标签**（WM 反传得到的 `∂J/∂token`）已经采了 38,400 条，
蒸馏得到的头在**留出运动上方向精度只有 0.31–0.41**（cos），闭环 18 对配对**没有任何成功率收益**
（9/18 vs 11/18，McNemar p=0.625），且**站桩显著变多**（13/18，p=0.048）。
诊断结论：**瓶颈是"标签里可学的信息量"，不是模型容量、不是视觉、不是视界、不是任务覆盖。**

## 1. 部署链路（推理时**不含**世界模型）

```
相机 (ego view 256×256) + state46
        │
        ▼
GR00T N1.7  VLA   = Cosmos-Reason2-2B backbone (frozen) + 1.09B DiT action head (fine-tuned)
        │   64 维 motion token chunk (T=40, 50 Hz ⇒ 0.8 s)
        ▼
  [ Δtoken 残差在这里加：token' = token + Δ ]     ← 我们唯一训练的模块
        │
        ▼
SONIC decoder (ONNX, CPU EP)  ⇒ 29 关节目标 (50 Hz)
        │
        ▼
Isaac / 真机执行
```

* 闭环里**没有** WM（世界模型）；WM 只在**离线采标签**时用来反传。
* 每个 chunk 执行约 2.6 s（含 server 往返）；一次闭环评测 = 3 任务 × 6 seed × 3000 步 ≈ **3 小时**。

## 3. 教师标签是什么、怎么来的

```
ε = 共享扰动 (64)
token'_t = token_t + ε           # 完整 chunk 上共享
a_t      = SONIC_decoder(token'_t, obs_t)      (冻结)
s_{t+1}  = WM(s_t, a_t, ξ)                     (冻结)
J_H      = Σ_{t<H} γ^t · survival_t · r_t      (与主训练同定义)
g        = dJ_H/dε   （一次 20 步反传）
```

* 逐帧版本：对每个 `token_t` 独立求导（`tokenwise_reward_grad`）⇒ `g_tok_pert (T,64)`。
* 单条成本（实测）：H=20 **1869 ms**、H=10 987 ms、H=5 439 ms、H=2 231 ms、纯前向 88 ms。
  （所以 38,400 条要跑很久；这也是为什么降 H 在经济上有吸引力。）

## 4. 实测结果（全部标注口径）

### 4.1 真机（Isaac）梯度真值探针：**动作空间**

做法：从真实窗口取 `s₀, a₀`，用 WM 反传得 `ĝ=∂J/∂a`，归一化到 RMS δ=0.03 rad，
在同一 `s₀` 执行 `a₀ ± δĝ` 走 H 步，用**同一个** reward 结算。

| 视界 | 窗口 | 符号一致率 | ΔJ 相关 | J_true | J_WM | 幅值比 |
|---|---|---|---|---|---|---|
| H=2 | 96 | **1.000** | **+0.964** | +0.0076 | +0.0087 | **1.14×** |
| H=20 | 64 | **0.984** | **+0.092** | +0.0587 | +0.1277 | **1.79×（中位）/ 2.17×（均值）** |

**读法**：WM 的**符号**可信（98.4%）；**幅值与排序不可信**（0.092）。
脚本：`scripts/probe_wm_gradient_truth.py`；日志 `logs/truth_probe*.log`。
⚠️ 口径限制：这是**动作空间 29 维**的验证，**不是** token 空间的证明。

| token 逐帧（第 0 帧）| 1 | 0.508 | 好学但不准（见 4.3） |
| 动作 共享 (29) `g1` | **1** | 0.505 | 注意是 1 步，不是空间优势 |

同族/跨族对照（逐帧 20 步目标）：

## 5. 失败机制（我们的诊断）

### 5.1 为什么 0.41 不够：盈亏平衡是 cos = 0.707

施加的 Δ = `η·(cos·ŷ + sin·n̂)`：
* cos = 0.707 时正确分量 = 错误分量；
* **cos = 0.41 时 sin = 0.91 ⇒ 错误分量是正确分量的 2.2 倍**；
* 一阶改善 ∝ cos，但"能拿到的改善比例" ∝ cos² ⇒ **0.41² = 17%**。

经验锚点：cos 0.459 的 S 臂闭环无收益，且**站桩显著增加**（p=0.048）。

### 5.2 为什么可学性停在 0.4：三个"信息源"都排查过了

| 可能的信息源 | 实测增益 |
|---|---|
| 视觉（2048 维 backbone 特征） | **+0.007**（与打乱对照重叠） |
| 参考动作 ref0（神谕） | +0.04 |
| 任务覆盖（多族 vs 少族） | +0.04 |
| 架构/容量（ridge / MLP / temporal / Transformer + GRU） | 全在 0.37–0.41 |
| 视界（20 → 1） | +0.19，**但方向保真崩到 0.355** |

⇒ 目标 `∂J₂₀/∂token` 对现有观测而言，**大部分是不可约噪声**。

### 5.3 报酬反传（BPTT）为什么也不行

历史结果（`docs/DELTA_TOKEN_TRAINING_VERDICT.md` §4.1）：
v10/v11/v13（LoRA rank 32 = 34.1 M + `λ_r·reward`）**学到常向量**（跨臂 cos 0.95–0.997）；
反常量项 0.03/0.1/0.3 三档都失败（残差/均值 0.164/0.170/0.081）；
bptt1（λ_r=2.8 + 逐窗口归一化）43 步 `rollout/reward +1.5%` 但 `act/rmse +98%`（薅 WM）。

机制：参数梯度 ≈ `Σ_w g_w ⊗ φ(x_w)`，早期输出对所有窗口近似相同 ⇒ 一步跳到**平均方向**。

### 5.4 v13 的"教师蒸馏项"其实是空转的（重要更正）

`runs/joint_v13` 配置里同时有 `lambda_r=5.0`（报酬）和 `action_target_weight=1.0, eta=0.15, steps=20`（动作空间教师梯度）。
但逐条 metric 显示 `loss/action_target` 全程钉在 **0.0225 = η² = 0.15²**：

| step | loss/action_target | action_target/rms | act/rmse |
|---|---|---|---|
| 1 | 0.0437 | 0.15 | 1e-06 |
| 8 | **0.02246** | 0.15 | 0.0051 |
| 39 | **0.02341** | 0.15 | 0.0166 |
| 100 | **0.02780** | 0.15 | 0.0561 |

⇒ 该蒸馏项**没有产生梯度**，v13 实际只被报酬反传驱动 ⇒ 30.8% 的闭环结果不能用来否定"LoRA+蒸馏"这个组合。

## 7. 尚未验证 / 不能声称的

1. **Gate B**：`token ± Δ` 在真机里是否是上升方向 —— **从未测过**。
   已测的只有**动作空间**（§4.1）。token→动作要过 SONIC 解码器（80 Hz 策略网络 + PD + 时延），方向可能被扭曲。
2. **token 空间 ΔJ 配对**：`J_isaac(+Δ) vs J_isaac(0)` 未测。
