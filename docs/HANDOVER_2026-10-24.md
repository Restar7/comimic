## 1. 项目是什么

一条主线：**VLA（Cosmos-Reason2-2B + GR00T-N1.7 action head）输出 64 维 SONIC motion token
→ 全身控制（WBC）→ 人形机器人动作**，并研究「把下游任务的奖励反传回 VLA」这件事。
围绕它现在有**两条并行的产品线**：

### 1.1 MuJoCo 线（我们自己搭的，已能训练 + 评测）

```
GR00T VLA ──token64──▶ SuperMimic Policy（token 条件化）──▶ SuperMimic WorldModel（神经网络动力学）
                                                                    │
                                                                    ▼
                                                        解析 tracking reward ──反传──▶ VLA head
评测：GR00T VLA ──token64──▶ SONIC decoder(ONNX) ──29 关节──▶ MuJoCo PD ──▶ 成功率/视频
```

- 训练器：`scripts/train_joint.py` + `diff_vla_wbc/`（纯 torch，可微，**训练时不跑任何物理引擎**）
- 闭环评测：`closed_loop/code/mosaic_n17/tools/closed_loop_mujoco.py`（**MuJoCo**）
- 已有产物：`runs/joint_diff_ft318/vla_004000.pt`（4000 步反传微调）、`runs/ckpt_vla_ft4000`（合并后可直接推理）

## 2. 组件归属（今天核实过；更早的文档在这点上是错的）

| 组件 | 谁的 | 训练/来源 | 证据 |
|---|---|---|---|
| 64 维 motion token **encoder** | **SONIC** | Isaac Lab（PPO+aux） | `model_encoder.onnx` 在 SuperMimic 与 SONIC release 里是**同一个文件**（50 100 513 B） |
| **部署用 decoder**（token→29 关节） | **SONIC** | 同上 | 闭环：`SonicController(release/model_decoder.onnx)`；`token(64)+10 帧历史→994→29` |
| **WBC 策略**（训练时的执行器） | **SuperMimic** | mjlab / MuJoCo-Warp | `supermimic/policy/nets.py` 的 `PolicyCfg.encoder_hidden/decoder_hidden`，**自带 encoder+decoder MLP** |
| **世界模型** | **SuperMimic** | 同上 | `supermimic/world_model/world_model.py` |
| VLA | 我们 | 官方 GR00T 微调（纯监督） | `runs/groot_sonic_vla_20k_*` |

**关键结论（务必记住）**：
1. **训练时完全没有 SONIC decoder**，编码/解码都是 SuperMimic 自己的 MLP，全链纯 torch、可微、无物理引擎；
   `build_g1_assets()` 只加载 MuJoCo 模型 + FK，一个 ONNX 都没有。
2. SONIC 的 encoder/decoder 只出现在两处：**数据标注**（造 token 监督）和**闭环部署**。
3. 因此当前存在「训练用 SuperMimic、评测用 SONIC decoder」的**执行栈不一致**（§9.1）。

## 8. 已知坑（按症状查）

1. **`ModuleNotFoundError: No module named 'tyro'`** → 真实 GR00T head 需要
   `sys.path` 里有 `third_party/gr00t_deps`。
2. **`AttributeError: ... 'eglQueryString'`** → 缺 `libEGL`；这是别的机器的问题，本机 `EGL` 正常；
   无 EGL 时设 `MUJOCO_GL=disable`。
3. **闭环脚本选错**：`closed_loop/code/closed_loop_mujoco.py`（旧，**没有** `--hand-mode`）和
   `closed_loop/code/mosaic_n17/tools/closed_loop_mujoco.py`（**新的、带手部流的**）是两个文件；
   `run_tasks.sh` 与 `success_rate.py` 用的是后者。报 `unrecognized arguments: --hand-mode` 就是选错了。
4. **`vla_<step>.pt` 不能直接当 checkpoint 用** → 必须先用 `export_vla_ckpt.py` 合并。
5. **四元数顺序**：我们 npz 是 **WXYZ**，trackerlab 的 CSV 要 **XYZW**；转换器已处理。
6. **上游 MotionLib 默认 `src_fps=30`**，我们数据是 50 Hz → 用 `prepare_token_data.py` 产的
   `meta.json`（`from_dir` 会自动读），别手搓 CSV。
7. **C++/CUDA OOM 不会杀别人的进程**，但会让你的进程死；`success_rate.py` 会把该 episode 记为
   `failed_to_run` 并继续（下次重跑会重试）。
8. **ddp 启动前**：`train_joint.py` 若某 rank 先死会留下僵尸，`pkill -f train_joint.py` 清理。
9. **H200 不能跑 Isaac Sim**：H200/H100 无 RT core，Isaac Sim 建渲染设备会失败
   （`No device could be created`）。Isaac 线的训练只能在 **4090** 上。
10. **`--time-budget-minutes` 与 `--steps` 同时存在时**：`steps` 设大（如 1000000），让时间预算生效。
11. **`adjoint` + `--train-vlm` 不兼容**：adjoint 会 detach backbone 特征（会打 RuntimeWarning），
    要训 VLM 就用 `pathwise`。
12. **`qvgm_lite` 在真实栈里没有**：会显式 `SystemExit`，只能用 `ablation_fm_grad` 的 toy/tiny harness。

### 13.2 硬约束：BONES-SEED 塞不进 trackerlab 的 MotionLib

`trackerlab` 的 `MotionLib` **预计算 FK**：每帧约 623 float（2.5 KB）
= `root_p/R/v/w + q/qd` + 30 刚体 `body_p/R/v/w` + 局部速度。

- LAFAN1 3.6 万帧 → 90 MB；
- **BONES-SEED 4,750 万帧 → ~118 GB**（48 GB 的 4090 装不下，96 GB 也不行）。

出路：① 子采样到 ~40–60 h（≈2–3 万 clip，预计算 FK 约 18–27 GB）；
② 移植紧凑存法（只存 `ref`，142 B/帧，全量 6.28 GiB 能进卡），改造点：
`MotionLib` 的 body_* 预计算、`MDP.reward` / `MDP.critic_features` 里的 `m.body_p[f]` 索引、
`MotionManager.reset` 的返回。

### 13.3 到平台的成本（用 SuperMimic 论文自己的 scaling）

`PAPER_SPEC.md` 数据长度扫描（到目标回报的 GPU 小时，H100 + MuJoCo-Warp）：

| 数据量 | 1 h | 7 h | 40 h | 264 h |
|---|---|---|---|---|
| GPU 小时 | 0.5 | 1.3 | 1.8 | **1.9** |

**曲线饱和**：40 h → 264 h 只涨 0.05 GPU-h，所以全量 BONES-SEED 不比 40 h 子集贵。

但 Isaac Lab 吞吐只有 MuJoCo-Warp 的 ~1/12（实测 1.1×10⁴ env-steps/s @PRO6000/8096envs，
4090 约 8×10³；Warp 参考 1×10⁵）。换算：

| 路径 | 到平台 |
|---|---|
| Isaac Lab + BONES-SEED（单 4090） | **~85,000 迭代 ≈ 20–25 h** |
| Isaac Lab + 40 h 子集 | ~80,000 迭代 ≈ 22 h（只省显存，不省时间） |
| 上游 MuJoCo-Warp（现有 `ckpt_0024000.pt`） | 24,000 迭代，2×H200 约 4 h |

**4 卡不会加速单次训练**：`trackerlab` 无 torchrun/DDP（grep 零命中），4 卡 = 4 个 seed 并行。
唯一能加速的旋钮是 **num_envs**（4096/8096/12288 扫描）——时间维度不可并行。

  `InteractiveScene`/`InteractiveSceneCfg`/`SimulationCfg`/`SimulationContext`/`configclass`）。
- 上述模块与符号在 **2.2 与 2.3.2 中均存在**（模块级差异 0；符号级在 2.2 全树可解析）。
- 我这边试跑 5.0 时唯一的报错是 `ModuleNotFoundError: No module named 'flatdict'`
  ——**依赖缺失，不是 API 不兼容**。

```bash
               mujoco==3.3.7 scipy matplotlib pillow imageio-ffmpeg opencv-python-headless
```
