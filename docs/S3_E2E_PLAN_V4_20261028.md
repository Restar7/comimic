# S3 端到端联合微调：**v4 完整方案（2026-10-28 重构版）**

> **本文是唯一的端到端方案**。`S3_END_TO_END_PLAN_20261028.md` / `S3_END_TO_END_V3_PLAN` 降级为历史记录。
> **只写还没解决的问题**；已经改完的不再重复，见 `docs/RUNBOOK_S3_HANDOFF_20261028.md` §5。
>
> 定位一句话：**让 head（可选连同 WBC）在真物理闭环里的"执行漂移"最小**。
> 判据是 `e_root(t)` 曲线 + 摔率；**不是** `token_mse`，**不是**想象回报。

---

## 0. 流程总览

```
第 k 轮：
 [1] B 线采集（π_k，真物理闭环，随机起点，关录像，落盘 VLA 输入）
 [2] WM 刷新（B 数据 ≥50% + 已有数据）→ 留出 B 片段做**多步**验收
 [3] 想象反传（起点 = B 重规划状态；中心 = π_k；WBC 冻结/解冻可选）
 [4] 真物理闭环验收（≥3 seeds，漂移曲线 + 摔率，和 GT online 同 harness 比）
 π_{k+1} → 回 [1]
```

**每轮 200–300 次参数更新**（≈ 一轮 600 步采集的 0.3–0.5 UTD），**转 3–5 轮**。不是一次长跑。

## 1. 与 SuperMimic 的关系：同构，但有 4 处差异

### 1.1 同构（骨架一样）

| SuperMimic | 我们 |
|---|---|
| collect → fit WM → improve policy | 同一条循环 |
| WM 用**当前策略**的 on-policy 真转移刷新 | 同（`--extra-transitions`，B 数据 ≥50%） |
| 在**冻结 WM 的想象里**反传执行误差 | 同（H=20，可微 WBC+WM） |
| **不学标签**，只学回报 | 同（`lambda_bc=0`） |
| 随机起点 + 域随机化 | 同（B 重规划起点；采集侧随机起始帧待补，见 O3） |

### 1.2 差异（都落在会决定成败的地方）

| # | SuperMimic | 我们 | 后果 |
|---|---|---|---|
| D1 | 策略直接输出 **29 维动作**，能学**反射** | head 输出 **64 维 token**，低层 WBC 冻结（可选解冻） | 只能学"要哪段运动"；权利有限 → 必须先验 G0-a |
| D2 | **4096 env** 持续采，UTD 0.4，batch 4096 | 1 env/进程（可 4 并行），batch 32，**UTD ≈ 0.004** | 差 ~100×；信任域（中心 π_k）是替代品 |
| D3 | 仿真器**一直在环里**，接触由真物理给 | 离线：一轮采完才训 | WM 看不到接触，只能靠**压漂移**间接减少碰桌 |
| D4 | 4.8M MLP，单次反向 <1 s | 1.62B DiT（LoRA 33.5M），单次 **16–18 s** | 在线高频更新不可能，所以走"分轮" |

## 2. 当前可训练图（代码现状）

```
[VLA backbone 冻结]
      │
      ▼
[action head 1.62B] ── LoRA r=32（33,554,432 可训）──► 64d token
      │
      ▼
[WBC 4,799,517 参数] ── 冻结（默认）｜ 解冻（TRAIN_WBC=1，新开关）──► 29d 动作
      │
      ▼
[WM（冻结）] ──► s' ──► [解析奖励 + 解析 survival] ──► loss = −λ_r·(ret + boot) + λ_act·hinge
```

**开关（都已落地，冒烟通过）**

| 开关 | 取值 | 说明 |
|---|---|---|
| `V3` | 0/1 | 必须 1，否则 trust/act/lambda-hand 全空转（启动器已加 WARN） |
| `TRUST_CENTER` | `prev`（推荐）/`label`/`base` | `prev` = 本轮 π_k 冻结快照（LoRA），同一噪声、无标签 |
| `TRAIN_WBC` | 0（默认）/1 | 解冻执行器（"直接学动作"的对照臂） |
| `WBC_LR` | 1e-5（冒烟）/ **建议 1e-6** | WBC 学习率；1e-5 时一步就能把 `act/rmse` 推到 0.18 |
| `ACT_EPS` / `ACT_WEIGHT` | 0.6/1.0（head 臂）；**0.3/1.0（WBC 臂）** | 动作 hinge 的球半径：base-vs-label 实测 0.21，0.3 ≈ 1.4× |
| `START_FROM_B` | `runs/B_*/dump/*.pt` | 起点 = B 线真实重规划状态（不 burn-in、不叠 DR） |

### 2.1 解冻 WBC 的语义与安全边界（本轮要试的实验）

- **token 的定义不变**（由冻结 encoder 决定）⇒ VLA 的 BC 标签**不作废**；改的只是"token → 动作"的 decoder。
- WM **仍然冻结**：裁判不能跟着策略一起变，否则等于"自己改规则"。
- 动作 hinge 的中心 = **π_k 的 WBC 快照**（`deepcopy`，19 MB），因此 hinge 约束的是**行为变化**（head 引起 + WBC 引起的总和），不是参数距离。
- 导出：`joint_*.pt` 里的 `pi` 就是训练后的 WBC，闭环用 `SM_CKPT=joint_*.pt` 直接加载。
- 风险（必须写进结论）：
  1. WM 看不见接触 → WBC 可能学"在想象里推桌子"；
  2. 遗忘：现在 699 clip 100% 不摔 / 0.0818 rad，训坏必须能回滚（保留 π_k 的 ckpt）。

## 3. k 轮闭环：逐阶段命令与判据

### [1] B 线采集（π_k）

```bash
OUT=$PWD/runs/B_r${K}_$(date +%H%M); mkdir -p $OUT/dump
env -u LD_LIBRARY_PATH -u LD_PRELOAD \
  TASK=DoubleDesk SEED=0 MAX_STEPS=600 ISAAC_GPU=0 \
  MODEL_LABEL=vla_${K} OUT_ROOT=$OUT/runs \
  SM_CKPT=$PWD/runs/S1_handover/WBC_A24000_wmvel_v2.pt \
  SM_TOKEN_SOURCE=http SERVER_URL=http://127.0.0.1:18080 SM_HAND=1 \
  SM_DUMP_STATES=$OUT/dump/DoubleDesk HA_VLA_EXEC_STEPS=20 \
  SM_INIT_FROM_LIB=1 SM_START_FRAME=2080 SM_HAND=0 \
  RECORD_VIDEO=0 \
  bash scripts/ha_isaac_closedloop.sh > logs/$(basename $OUT)_DoubleDesk.log 2>&1
```

**采集验收（三条）**
1. 每条落盘、`states` 行数 = 实跑步数；
2. `q_target_applied`/`tokens` 非空，`frames` 单调且 = 真实库行号（`meta.frames_source == "library_row"`）；
3. 摔的比例：≥4/5 不摔（摔了的那条入库但标记）。

### [2] 真奖励 + 真转移 + WM 刷新

```bash
SUPERMIMIC_HA_ALIGN=1 PYTHONPATH=.:third_party/SuperMimic-Reproduced/src \
  python3 scripts/compute_collect_reward.py --in $OUT/dump/*.pt --out $OUT/scored --device cuda:1

PYTHONPATH=. python3 scripts/build_real_transitions_v2.py \
  --out runs/wm_real/real_transitions_v2.pt --extra-dumps "$OUT/scored/*_r.pt"

PYTHONPATH=. python3 scripts/finetune_wm_velocity_policy.py \
  --ckpt runs/S1_handover/WBC_A24000_wmvel_cmd.pt --out runs/S1_handover/WBC_A24000_wmvel_v2.pt \
  --packed runs/isaac_motion/ha_cmd/packed.pt --token-space label --steps 800 --batch 256 \
  --lr 1e-4 --vel-lambda 5 \
  --extra-transitions runs/wm_real/real_transitions_v2.pt --extra-frac 0.5
```

**验收（G0-b）**：`eval_wm_velocity --tokens label --packed ha_cmd` 上 `qd_corr ≥ 0.70`
且不比上一版低 0.03 以上；**另加**：在留出 B 片段上做**多步**预测误差（见 O2），不能比上一版差。

### [3] 想象反传

```bash
V3=1 TRUST_CENTER=prev START_FROM_B="$OUT/dump/*.pt" ACT_EPS=0.6 ACT_WEIGHT=1.0 \
LAMBDA_R=0.3 LAMBDA_BC=0 RUN=s3_r${K} BATCH=4 ACCUM=8 H=20 K=4 \
EVAL_EVERY=100 EVAL_BATCHES=8 SAVE_EVERY=100 \
WBC_CKPT=$PWD/runs/S1_handover/WBC_A24000_wmvel_v2.pt \
EXTRA="--amp bf16 --lora-rank 32 --fm-lr 1e-4 --no-dr --vla-state-from-burnin \
       --no-critic --act-hinge-cap 2 --lambda-hand 0.2" \
bash scripts/launch_joint_ha_v2.sh
```

WBC 对照臂额外加：`TRAIN_WBC=1 WBC_LR=1e-6 ACT_EPS=0.3`。

**训练验收（三条）**
1. 无 NaN；`codec/out_of_range` 不随步数单调上升；
2. `token_mse` 变化 ≤ 1.5×（canary，不是成绩）；
3. `act/frac_out` 不要长期贴 1（贴 1 = 一直顶墙，梯度方向只剩约束）。

### [4] 闭环验收

```bash
# head 换进 server（--head-ckpt 见 O14），然后同 [1] 的 harness 跑，RECORD_VIDEO=1
TASK=DoubleDesk SEED={0,1,2} MAX_STEPS=600 ... SM_CKPT=runs/s3_r${K}/joint_final.pt ...
```

**唯一判据**：`e_root(t)` 的 300/600/2000 步值 + tilt + 摔率，**≥3 seeds**，与 GT online 同起点同 harness 比。
提升必须超过 seed 间波动；否则判"无实质改进"。

## 4. 未解决问题清单（只列**还没改**的）

> 每条：现象 / 影响 / 方案 / 判据 / 成本 / 是否阻塞。

### O1｜token 有没有"权限"（**最优先**，阻塞"值不值得投"）
- **现象**：GT token 是 WBC 的训练条件，但 WBC 有 ~0.08 rad 系统跟踪误差；一个"补偿型" token 可能更好，也可能无效。没测过。
- **影响**：如果 ORACLE（想象里优化出的最优 token）在真物理里也不比 GT 好，则 head 训练上限 = GT，投多少轮都是白跑。
- **方案**：三臂 online 各 2000 步：GT / ORACLE / VLA π₀，同 harness 同起点。
- **判据**：ORACLE 的 `e_root(t)` 显著低于 GT（> seed 间波动）⇒ 继续；否则止损回 WBC 侧。
- **成本**：1 h。**阻塞？** 阻塞第 2 轮起；第 1 轮可以先跑。

### O2｜WM 多步验收：**已实现，且 v2 刷新件 FAIL**（2026-10-28）
- **工具**：`scripts/eval_wm_multistep.py`——从 B 线重规划状态出发，用**真实动作**滚 20 步，逐步比关节/根/朝向/速度。
- **实测（B_baseline_2080，103 个起点）**：

| ckpt | k=1 joint | k=5 | k=10 | k=20 joint | k=20 root |
|---|---|---|---|---|---|
| base（`WBC_A24000_wmvel_cmd`） | 0.008 | 0.036 | 0.069 | **0.154 rad** | **9.2 cm** |
| v2（800 步刷新） | 0.008 | 0.043 | 0.091 | **0.214 rad** | 5.8 cm |

  相对 base：v2 的 **20 步关节误差 +39%**、根误差 −37% ⇒ **G0-b（多步）FAIL**。
- **解读**：v2 的一步 `qd_corr` 略好（0.827 vs 0.834），但**多步更差** —— 典型的"一步过拟合"。
  训练用的是 H=20，所以 v2 **不能**进第 1 轮。
- **结论/动作**：
  1. 第 1 轮用 **base WM**（`WBC_A24000_wmvel_cmd.pt`），不要用 v2；
  2. 刷新流程要改：① `--extra-transitions` 混 B 数据；② 早停看**多步**而不是一步；③ 下一步考虑多步训练损失（2–4 步展开）。

#### O2.2｜多步刷新实测（2026-10-28，方案 1 落地）
`finetune_wm_velocity_policy.py` 新增：`--rollout-steps K`（2–4 步自回归展开）、
`--traj-dump`（B 长轨迹窗口）、`--traj-val-frac`（按时间切留出）、`--val-every`（多步早停）。

| 训练方式 | 留出 B 尾段 k=20 关节 | 根误差 | 结论 |
|---|---|---|---|
| base | 0.168 rad | 9.3 cm | — |
| K=3 多步、**只用录制库** | 0.199 → 0.244 | — | ❌ 越训越差（域不对） |
| K=3 多步 + **B 轨迹窗口 20%**（300 步） | **0.129 rad（−23.2%）** | **4.0 cm（−57%）** | ✅ **PASS** |

- **代价**：k=1 误差 +56%（0.008→0.012）、录制域的 `policy state` 0.089→0.218。
  ⇒ 新 WM 明显偏向"长视界 / off-reference"；训练起点正是 B 状态，所以**第 1 轮用 v4**，
  但每次轮换都要同时报录制域的数，别让它把短视界判断毁掉。
- **留出方式**：同一条 episode 的**时间尾段**（前 1560 步训、后 520 步验）；下一轮必须换成**另一条 episode**。
- **产物**：`runs/S1_handover/WBC_A24000_wmvel_v4.pt`。
- **判据（不变）**：留出 B 片段 20 步关节误差 ≤ 1.05× 上一版。**阻塞？** 是（第 2 轮起）。

#### O2.1｜回报级误差（2026-10-28 补测，决定"裁判分辨率"）
用同一批 B 窗口（103 个起点的 20 步），把 WM 预测的**折扣回报**和真实回报比：

| 量 | 值 |
|---|---|
| 真实回报 | mean 1.157 / std 0.179 |
| WM 预测 | mean 1.046 / std 0.256 |
| 误差 | mean **−0.110**（系统性低估 9.9%）/ std **0.192** |
| 预测-真实相关 | **0.663** |
| 窗口间真实回报差（信号） | mean 0.199 |
| **WM 误差 / 信号** | **0.96** |

- **解读**：20 步关节 RMSE 0.154 rad ≈ 每关节 8.8°，是策略自身跟踪误差（0.08 rad）的 **2 倍**；
  折算到回报，**误差 std ≈ 窗口间信号**（0.96×）⇒ 裁判**分辨不了**两个 token 的好坏。
- **但**：误差里有 9.9% 是系统性低估，**在配对比较（VLA vs GT，同一个 WM）里会抵消**；
  真正限制我们的是那 0.192 的**随机**部分。
- **动作**：
  1. 训练视界 **H=20 → 先试 H=10**（k=10 误差 0.069，约一半），用配对差而不是绝对回报；
  2. WM 刷新改成**多步损失**（2–4 步展开）+ 早停看多步；
  3. 唯一无偏裁判仍是**真物理 best-of-K**（贵，但结论只能由它下）。

### O3｜随机起点（root + 关节）——**代码已实现，采集命令必须打开**
- **现象（历史）**：`SM_INIT_Q_NPY` 只写 29 个关节；root 位姿还是 env 的 init pose ⇒ 起点不一致。
- **已实现**：provider 的 `SM_INIT_FROM_LIB=1` + `SM_START_FRAME=N`：从 `ha_cmd/packed.pt` 读该行的
  root xyz+quat、29 关节、qd，reset 时**一起写**；http 模式的参考行号游标也从 N 开始。
- **剩余（操作）**：采集命令里显式带上这两个变量；每集换 N（不同 clip / 不同起始帧）。
- **随机起点已完整**：`scripts/sample_start_row.py` 按任务随机挑 clip + 帧（SuperMimic 同款），
  `START_FRAMES=random` 自动调用。**env 侧不需要改**——HA 任务 env 没有运动参考
  （`commands=None`、`terminations` 空、reward 是物体任务、摔倒靠 tilt），
  参考只在我们的 provider 里。
- **判据**：t=0 根误差 < 1 cm、关节 RMSE < 0.02 rad（与 GT 同口径）。
- **成本**：0（已就绪）。**阻塞？** 否。

### O4｜采集时还在录视频
- **现象**：闭环 shell 默认 `--record_video_every_n 1`。
- **影响**：采集 600 步 × 多进程时，渲染/编码是纯开销（实时率 3.6 步/s 里有相当一部分）。
- **方案**：shell 加 `RECORD_VIDEO=0` 透传 `--record_video_every_n 0`（`_should_record_video` 对 0 返回 False）。
- **判据**：采集吞吐提升 ≥20%，且 dump 字段不变。
- **成本**：10 min。**阻塞？** 否。

### O5｜VLA 输入（ego 图像 / state46）还没落盘、训练侧也没消费
- **现象**：server 已有 `--log-dir`（`req_*.npz`：rgb / state64 / state46 / chunk），但采集命令没传；训练侧也不读它。
- **影响**：B 起点的 **图像仍然是录制 ego 帧**（本体感觉已用真实状态）。"VLA 看不到偏差"在图像通道上仍未解。
- **方案**：① 采集命令加 `--log-dir`；② `b_start.py` 读对应 `req_*.npz`，把 `rgb + state46` 拼成 `model_inputs`（复用 server 的 processor 路径）。
- **判据**：训练时 VLA 输入与 B 线当时的输入逐位一致（抽查 10 帧，max|Δ| < 1e-5）。
- **成本**：1 天。**阻塞？** 否，但决定方法上限（图像通道）。

### O6｜并行采集只到 4×，4096 级不做
- **现象**：单 env 3.6 步/s；GPU 空闲 40 GB，可同时 3–4 个 Isaac 进程（零代码，各跑不同 clip/seed，共用一个 server）。
- **影响**：数据量 ~4×，仍比 SuperMimic 少 ~1000×。
- **方案**：起 3–4 个进程；每轮轮换 clip。**4096 级**需要 HA 场景向量化 + 批量 VLA 推理，列为独立工程，**本阶段不做**。
- **判据**：4 进程并行时，单条 episode 的 token 流与串行一致。
- **成本**：半天（4 进程）。**阻塞？** 否。

### O7｜B 数据量太小 + 切分不严
- **现象**：现只有 1 条 episode（103 个重规划时刻）；train/eval 是**同一批 dump 按行号取模 5** 切的，不是跨 episode 留出。
- **影响**：eval 会高估（同一段轨迹的相邻时刻高度相关）；WM 验收的"留出片段"也不严格。
- **方案**：每轮 ≥3 条 episode（不同 clip/seed）；eval 按 **episode 留出**（1/5 集整条留出）。
- **判据**：留出集与训练集 clip 名不重叠。
- **成本**：随采集。**阻塞？** 阻塞 WM 验收的**可信度**。

### O8｜WBC 解冻实验（本轮新增，已实现未跑）
- **现状**：`--train-wbc/--wbc-lr` 已落地并冒烟：`trainable=head+wbc`，WBC 4,799,517 参数，参考 rollout 用 π_k 快照，step1 `act/rmse=1e-6`、step2 0.180，无 NaN。
- **风险**：① WM 无接触 → 学"推桌子"；② 遗忘（699 clip 100% 不摔）；③ 行为变化比 head 快得多。
- **方案**：臂 A = head only（主）；臂 B = head+WBC（`WBC_LR=1e-6`、`ACT_EPS=0.3`）。其余完全相同。
- **判据（三条同时）**：① B 臂的真物理 `e_root(t)` 低于 A 臂（> seed 波动）；② 自由空间不退化：`eval_wm_velocity` 的 `policy state` ≤ 0.10，或 699 clip 跑一次 `evaluate.py` 的 NR 下降 < 0.01；③ 不摔率不低于 A。
- **成本**：每臂 1 轮（~1.5 h）。**阻塞？** 否，是并行对照。

### O9｜LoRA 还是全量：**定 LoRA r=32 为默认，全量只作对照**
- **依据**：底模与标签 token MSE 0.0047；VLA 在录制状态上想象回报只差 GT 0.2–2% ⇒ 需要的是"小补偿"。全量：26 GB、batch 4、35 s/step；LoRA：0.33 GB、batch 32、16–18 s/step。
- **判定**：若 LoRA 训到 `act/frac_out` 长期为 0 而漂移不降 ⇒ rank 不够，升 r=64 或开全量对照臂。
- **成本**：全量对照 1 轮。**阻塞？** 否。

### O10｜UTD/批次差距（结构性，接受）
- **数字**：1 次更新 16–18 s，4 env ≈ 14.4 step/s ⇒ UTD ≈ 0.004；SuperMimic 0.4（差 ~100×）。batch 32 vs 4096（128×）。
- **影响**：不能在线高频更新；WM 覆盖不了当前策略的整个分布。
- **方案**：接受；用"分轮采集 + 每轮 200–300 步 + π_k 信任域"替代持续覆盖；每轮结束必须重采。
- **判据**：每轮 WM 留出多步误差不升（O2）。
- **阻塞？** 否（这是方法的前提，不是待修 bug）。

### O11｜WM 里没有物体和接触（本阶段不做）
- **影响**：想象里永远预测不到"手撞桌 → 倾倒"；只能靠**降低漂移**间接减少接触。
- **方案（本阶段）**：不扩物体 WM；把目标定成"漂移曲线逼近 GT"。若两轮后 `e_root` 降了但摔率不降，再评估扩物体状态。
- **判据**：`e_root` 降、摔率不变 ⇒ 说明摔因不在漂移，转向 WBC/接触（另一条线）。
- **成本**：扩物体 WM ≈ 2–4 周。**阻塞？** 否。

### O12｜critic：**离线重训实测过，门没过**（2026-10-28 结论）
- **旧现象**：`v_ev = −0.47/−1.29/−1.84`（训练 minibatch 上的数，不是留出集）。
- **这次做了什么**：
  1. `scripts/fit_critic_real.py`：按 **episode 留出**（559 训 / 140 验），在真转移上监督拟合，报留出 `v_ev`；
  2. 数据 = 录制 634k + B 漂移 2080；目标 = MC return-to-go，四种口径（none/mean/linear × 是否显式吃 `s−ref`）；
  3. critic 加了 `use_diff`（显式喂 `s−ref`，价值几乎全由偏差决定）。
- **实测（留出 140 clips）**：

| 目标口径 | 特征 | 最佳 epoch | **留出 v_ev** |
|---|---|---|---|
| linear（去时间趋势） | `[s, ref]` | 1 | **−0.13** |
| linear | `[s, ref, s−ref]` | 1 | **−0.06** |
| mean（去 episode 均值） | `[s, ref, s−ref]` | 1 | **+0.21** |
| none（原始 MC） | `[s, ref, s−ref]` | 2 | +0.04 |

- **解读**：`mean` 上的 +0.21 主要来自"剩余步数"的趋势（能从参考姿态读出相位）；**真正有用的、状态相关的那部分（linear 去趋势）是负的** ⇒ critic 学不到"偏了之后还能拿多少"。
- **根因**：数据 99.7% 是 **on-reference**（参考执行），而 bootstrap 用的是 **off-reference** 的 `s_H`；这部分只有 2080 行（0.3%）。
- **方案（按顺序）**：
  1. **每轮 B 采集都进 critic 目标**（`--extra-dumps` 已在 `build_real_transitions_v2` 里）；B 累积到 ≥1 万行再重评；
  2. `v_ev` 拆开报：**录制留出** + **B 留出**，门只看 **B 留出 > 0.3**（那才是它工作的地方）；
  3. 特征先用 `use_diff`；不够再把参考**窗口**（未来 10 帧）而不是单帧喂进去；
  4. 口径定 **linear 去趋势**（去掉"剩余步数"，避开滞后诱导）。
- **现状**：门**未过**（最佳 +0.21 < 0.30）⇒ critic 默认仍关（启动器已加 `--no-critic` 默认）。
- **但可以试**：已落地的 **臂 C = with critic**（`CRITIC_ON=1 CRITIC_CKPT=... CRITIC_USE_DIFF=1`），判据是真物理 `e_root`，不是 `v_ev`。
- **成本**：重评 10 min；臂 C 一轮 ~2.5 h。**阻塞？** 否。

### O13｜评测口径还不严
- **现象**：现在单 seed、单条 episode；`success` 恒 False；没有批量评测器（P0-1）。
- **影响**：`e_root` 的差异可能小于 seed 波动，结论不可靠。
- **方案**：≥3 seeds 配对；同 harness 同起点；同时报 `e_root`、tilt、摔率、env `success`；GT online 曲线作上限。
- **判据**：同配置 3 seeds 的 `e_root` 波动 < 20% 才算"数字稳定"。
- **成本**：每个配置 ~15 min。**阻塞？** 阻塞"宣布有效"。

### O14｜server 还不支持 `--head-ckpt`
- **现象**：`ha_vla_latent64_server.py` 只能加载完整 VLA ckpt，不能只换 action head。

- **判据**：换 head 后同一输入 token 与离线推理逐位一致（max|Δ| < 1e-4）。
- **成本**：10 行。**阻塞？** 阻塞闭环验收。
