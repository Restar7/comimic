## 4. 今天定案的两处口径 bug（都已修，且都有 bit 级验证）

### 4.1 WM 的动作序（**致命**）

`SonicExecutor.act` 返回 **STANDARD 序**，而 WM 是拿 **SONIC 序**动作训的 ⇒ 微调时 WM 收到的动作被**整体置换**（置换幅度 1.41，动作量级 0.945）。

| 量化 | 数值 |
|---|---|
| 同一批动作滚 20 步，奖励 | 正确 **+0.0173** vs bug **−0.0584**（**−438%，翻符号**） |
| 20 步末态误差 | +11.1% |
| 修复后等价性 | `max\|Δ\| = 0.000e+00` |

**修复**：`diff_vla_wbc/sonic_isaac.py::SonicIsaacBundle.step` 里 `action.index_select(-1, std_to_ha)` 再喂 WM（默认 `wm_wants_sonic_order=True`）。

### 4.2 奖励里的动作单位（惰性，但已修）

MDP 的 `action_rate` 用 `(a−a_prev)×action_scale`（**HA 口径**），而动作是 SONIC 单位。
**换算** `a_ha = a_sonic×SONIC_SCALE/HA_SCALE` 后与录制 q_target 的真实弧度差 **2.4e-7**（不换算 **131%**）。
注意：`joint_limit` 用的是**状态 q**、不吃动作；`action_rate` 实测为 **0.0** ⇒ 实际零影响。
**修复**：`SonicIsaacBundle.reward`；换算实现唯一化在 `diff_vla_wbc/reward_cfg.py`。

## 5. 三个「真物理」实验（今天最重要的证据）

**设置**：48 个真实窗口、`δ=0.15` SONIC 单位（≈3.3°/关节）、同一状态、两串动作各在 Isaac 里滚 20 步、比"相对参考的位置漂移"。

| 方向 | WM 的判断 | **真物理同号率** | **真物理漂移变化** |
|---|---|---|---|
| **∂J_WM/∂a（WM 梯度）** | + | **33/48 = 69%** ✅ | **−1.23 cm（变好）** |
| FT **v10** 实际造成的动作位移 | +（ΔJ=+0.029） | **17/48 = 35%** ❌ | −0.11 cm |
| FT **v11**（trust 0.5→0.2） | + | **25/48 = 52%** ❌ | +0.04 cm |
| FT **v13**（动作空间回归 P1，20 步） | + | **20/48 = 42%** ❌ | −0.11 cm |
| 参照：WM 的 20 步保真误差 | — | — | 0.89 cm（⇒ 信号/误差 ≈1.4） |

**结论链**：
1. **WM 没训错**：它的 20 步方向在真机有效（69%、−1.23 cm、SNR≈1.4）。够用、不精确。
2. **奖励也不是主因**（单步差分增益比 0.90–1.00、方向余弦 0.97–0.98、留出泛化 1.72）。
3. **错在"方向落实"**：无论是直接反传（v10/v11）还是"动作空间目标 + 回归"（v13），策略实现出来的动作变化都不是那个方向。
4. **因此瓶颈是 `token(64) → decoder(994 维观测) → 动作(29)` 这条通道的分辨率/表达能力**。

## 6. 联合微调：当前实现与参数

### 6.1 损失（`v3` 分支）

```
loss = λ_r·(−ret)                                   # 主项：想象漂移奖励，λ_r=5.0
     + act_weight · penalty(act_rms/act_eps)        # 动作刹车（l2 或 hinge）
     + trust_weight · relu(‖Δtoken‖/trust_eps −1)   # token 锚（中心=base）
     + λ_hand · hand_fm                             # 手部正则（手不参与）
     + action_target_weight · ‖actions[:k] − A*‖²   # P1（可选，默认 0）
     + 0                                            # λ_bc=0、token_bc=0
```
- `ret` = 想象 20 步的折扣回报（γ=0.95）；`REWARD_HORIZON=k` 可只取前 k 步（默认 0=满）。
- 奖励 `huber_err`：对 `√e` 做 Huber；`huber_delta 0.02 / cap 0.15 / d_pos 0.05 / d_ori 0.05 / d_vel 0.05 / d_max 0.30 / root_ori_mode split_huber / tail_weight 2.0 / yaw_hinge_lambda 0.3 / reward_vel_scale 1.0`。
- **口径唯一实现**：`diff_vla_wbc/reward_cfg.py`（训练与"补算奖励"都调它；与 `args.json` 还原后逐字一致）。

### 6.2 起点

`--start-source recorded` + `--start-max-drift 0.05`（保留 **61.9%** 行、起点漂移 **p50 2.38 cm**）+ **10 步 burn-in**（无梯度）。
⚠ **部署起点漂移 ≈0**，而训练起点 p50=2.38 cm ⇒ "零漂移起点"这一角没覆盖。

### 6.3 本轮实验过的配置（全部 100–500 次更新、3 卡 DDP、24 窗/更新）

| run | act 刹车 | trust | 奖励 | action-target | 更新 | act/rmse 末 | 想象 Δ | 真机 |
|---|---|---|---|---|---|---|---|---|
| v10 | l2 eps0.3 w0.2 | 0.5 | 满 20 | — | 500 | **0.170** | +0.032 | 配对 +4.47 cm，2/8 |
| v11 | 同上 | **0.2** | 满 20 | — | 100 | 0.077 | +0.018 | 方向 52% |
| v12 | 同上 | 0.2 | 满 20 | v1（**空转**） | 100 | 0.105 | — | 废弃 |
| v13 | 同上 | 0.2 | 满 20 | **v2：锚=base、20 步** | 100 | 0.060 | — | 方向 42%，但**闭环 net 1.221 / prog 0.427** |

**P1 v1 的 bug（教训）**：目标写成 `A0 + η·ĝ` 且 `A0=当前动作` ⇒ 损失 ≡ η²‖ĝ‖²、**梯度恒为 0**（日志里 `loss/action_target` 全程钉在 0.0225=0.15²）。**修法**：锚点改成 base 动作、回归步数默认 **20**（`--action-target-steps`）。

## 11. 未验证 / 诚实的不确定性

1. **20 步差分 SNR**：估 1.3（由单步 3.15 与误差涨 11 倍推得），实测版本只做了"同号率"（69%），**SNR 本身没直接测**。
2. **我的漂移指标只有 root 位置/朝向可信**：关节/速度列因"序 + 零位"未定而标记不可信；判定只用位置。
3. **`ret_gt`（标签 token）与 base 只差 0.7%**（0.4912 vs 0.4876）⇒ "奖励排序合理"这条证据是**弱**的。
4. **69% 的结论只在 48 个窗口、δ=0.15、语料起点上成立**；能否在 1000 步闭环里累积成更好的任务表现，**未验证**。
5. **任务层从未解决**：base 的 prog 只有 0.377。**"压漂移"与"完成任务"之间的联系没有证据**，这是下一个真问题（抓取/接触/时序），与 WM 无关。
