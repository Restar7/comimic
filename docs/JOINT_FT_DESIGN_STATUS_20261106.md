## 0. 十句话摘要（给 reviewer 的最短路径）

1. 目标是让 VLA 策略在 DoubleDesk（G1 29DoF + 三指手，全身）上**沿着参考运动跟得更准**，最终能完成"走到桌边→抓→绕到篮子→放"。
2. 交付基线（base，8 seed）：净位移 **1.065 ± 0.124 m**、沿示范进度 **0.377 ± 0.067**、离示范路径 p50 **3–18 mm**、零摔倒、**成功率 0/8**。
3. 失败形态已经定位清楚：**参考 10 s 走到桌边站住操作，20 s 后重新走到 2.00 m；机器人到 1.1 m 就不动了**，20→60 s 位移曲线完全水平（1.26 m）。
4. 我们**不走**"全长录制 A' + 整条轨迹和参考对齐"，原因见 §1.3：全长对齐压不下去，而且"走不同的路"本身是允许的，用全局对齐当目标会把合法路线判成错。
5. 我们走的是**局部收缩**：每 20 步（= 一次重规划 = 0.4 s）把偏差收一点，靠反复执行让整条轨迹不发散（§1.4）。这在理论上是对的（递推收缩），也是本文最需要 reviewer 确认的部分。
6. 联合微调的做法：**冻结 WM 当奖励**，对 VLA 的动作头做 LoRA（rank 32，33.5M 可训 / 2.03%），用 4 步流匹配的 pathwise 梯度把「想象 20 步的折扣回报」反传到 LoRA（§4）。
7. 四个动作臂（v10 / v11 / v13 / c1）全部**在想象里有效**（+1.3% ~ +5.7%），**在真机上没有正收益**：最好的一次配对闭环是 +4.47 cm（更差）、2/8；方向验收 42%（≈随机）。**注意：训练是多任务的，验收只在 DoubleDesk 上做**，其余 6 个任务未验（§6-P10）。
8. 我们后来把"为什么压不下去"定位到**四件独立的事**（§6）：起点太近（0–2.4 cm，而失败在 25 cm）、奖励在 30 cm 外梯度恒为 0、动作层残差改不动"站"这个命令、WM 的 20 步信号只有 1.23 cm 而其自身误差 0.89 cm（SNR≈1.4）。
9. 另一个关键事实：**命令（token）本身在站桩后输出"站"**（0.011–0.047 m/s 当量），这不是动作层能修的；给真值相位/真值 token 回放也**只到 0.85–1.13 m**（§5.7），说明瓶颈在命令下游或场景，不在"漂移"。
10. 最该先做的不是继续调联合微调，而是两件**诊断**：GT 动作回放（绕过 token/VLA）+ WM 在失败状态上的有效性；然后再决定是改输入（相位）、改奖励（死区）、改起点（dump 真实偏差）还是改交付口径（§8）。

## 1. 我们到底想解决什么，以及为什么这么设计

### 1.1 任务与观测到的失败

- 任务：`Isaac-Move-PickPlace-DoubleDesk-G129-Dex3-Wholebody`（HumanoidArena 7 任务之一）。
- 参考：`runs/isaac_motion/ha_cmd_exec/packed.pt` 的第 0 条 clip（`HOI_double_desk__tw__ep1776268633456387`，2080 帧 = 41.6 s）。
- 参考自己的时刻表（50 Hz，由 `body_pos_w[:,0,:2]` 差分得到）：

| 时段 | 0–5 s | 5–10 s | 10–15 s | 15–20 s | 20–25 s | 25–30 s | 30–35 s | 35–41 s |
|---|---|---|---|---|---|---|---|---|
| 平均速度 (m/s) | 0.110 | 0.227 | 0.089 | 0.072 | 0.166 | **0.367** | 0.211 | 0.112 |
| 距起点位移 (m) | 0.273 @5s | **1.181 @10s** | — | 1.174 @20s | — | **2.003 @30s** | 2.148 @35s | 1.963 @40s |

> 关键结构：参考 **10 s 到桌边 → 10–20 s 站住做操作 → 20–30 s 重新走到 2.00 m → 之后回到 1.96 m**。

- 机器人（base，8 seed 平均）：5 s 0.85 m、10 s 1.01 m、**20 s 1.07 m**；60 s 预算的 3 个 seed 在 20→60 s **一动不动**（1.26 m）。
- ⇒ 它不是"走不动"，也不是"慢"：**它把参考"走到桌边→站住"整段复现了（20 s 时只差 10 cm 直线位移），但参考 20 s 后重新起走的那一段，它没有跟。**

### 1.2 设计意图（用户原始思路，必须原样保留）

> "我们原本希望的是每一个起点都从参考出发，每 20 步的漂移不会太大，给它降低掉，然后让整体的漂移下降下去。"

展开成三条：

1. **局部**：每次只对"接下来 20 步"负责（20 步正好等于部署侧一次重规划：2.5 Hz × 20 步 = 0.4 s）。
2. **收缩**：只要每一步窗口结尾的偏差比开头小（`e_end < e_start`），反复执行几十次，整条轨迹的偏差就被压住了。
3. **不追求全局一致**：机器人走了另一条路不算错，只要它局部一直在靠近参考、任务能完成即可。

### 1.3 为什么放弃"全长 A' + 整体对齐"这条路

用户原话："第一个是全长录制发现偏移过多，整体压不下去；第二个是可能整体走不一样的路是允许的，不一定必须和参考一致，所以当时觉得整体不应该让他和参考相比。"

对应两个工程事实：

- **全长对齐不可压**：我们做过"全长录制 → 用 VLA 闭环复现整条轨迹"的路线（见 `docs/JOINT_MULTIROUND_PLAN_20261103.md`）。全长上偏差会**复利放大**，用"整条轨迹与参考的偏差"当目标时，损失被少数大偏差段主导，梯度方向被拖偏。
- **全局对齐是错的目标**：`prog`（沿示范弧长的进度）与 `d_path`（到示范路径的距离）都是"与参考一致"的度量，而任务允许绕路。用它们当**优化目标**会把合法路线判成错（metric gaming 风险，见 `docs/STALL_MECHANISM_AND_SA4_VERDICT_20261105.md` §5-N0）。
- 所以我们把目标降级成**局部 20 步**，全局指标只用来**判读**、不用来优化。

### 1.4 这个设计的正确数学形式（本文最需要 reviewer 确认的地方）

局部收缩的正确判据不是"20 步漂移的绝对值"，而是**每窗收缩增益**：

```
g(e) = ‖e_end‖ / ‖e_start‖        （同一个 20 步窗口，同一个偏差区间）
```

- `g < 1` ⇒ 递推有界，整条轨迹不会发散；`g ≈ 1` ⇒ 不动点（我们现在就是这种）；`g > 1` ⇒ 发散。
- **20 步能收多少？** 参考在 20 步（0.4 s）内最多移动 ~12 cm（0.3 m/s × 0.4 s）。所以**一个窗口的物理能力上限就是 12 cm**，30 cm 的偏差本来就不该靠一个窗口收掉。
- 若 `g = 0.8`，25 cm 收到 5 cm 需要 8 个窗口 = 3.2 s；若 `g = 0.9`，需要 16 个窗口 = 6.4 s。**两种都在允许范围内**。
- ⇒ "20 步 vs 25 cm" 不矛盾；矛盾的是**当前的 g 从来没有被测量过，也没有被当成训练/验收指标**（§6-P0）。

联合微调把它**关掉**（`lambda_bc=0`、`token_bc=0`），改用"想象漂移奖励"，梯度经 `--fm-grad-backend pathwise` 穿过 4 步采样。

## 4. 联合微调的完整实现

### 4.1 目标函数（`diff_vla_wbc/v3_step.py`，`v3` 分支）

```
loss = λ_r · ( −ret )                                        # 主项：想象 20 步折扣回报，λ_r = 5.0
     + act_weight · penalty(act_rms, act_eps)                 # 动作刹车：l2, eps=0.30, w=0.2
     + trust_weight · relu(‖Δtoken‖/trust_eps − 1)            # token 锚（中心=base）：eps=0.05, w=0.2
     + λ_hand · hand_fm                                       # 手部正则：0.05（手不参与）
     + action_target_weight · ‖ (D_pred−μ) − (D_tgt−μ) ‖²      # P1 动作目标：w=1.0, η=0.15, k=20
     + 0                                                      # λ_bc = 0，token_bc = 0
```

其中（这一段的精确口径对评审很重要）：

- `ret = discounted_return(rollout, γ=0.99)`，`H = 20` 步，`REWARD_HORIZON=0`（= 满 20 步）。
- `rollout = imagine_with_tokens(bundle, tokens=<VLA 头采样出的 token>, ...)` ⇒ **被优化的动作是"token → SONIC decoder → 29 维动作"这条链的输出**，不是 VLA 头的原始 78 维输出。
- `D_pred = rollout.actions[:k] − A0[:k]`，`D_tgt = A_tgt[:k] − A0[:k]`，`A_tgt = A0 + η·ĝ/‖ĝ‖_rms`，`A0 = base 策略的动作`（固定锚点），`ĝ = ∂J_WM/∂a`（在 base 动作处对 20 步 WM 回报求梯度）。
- `μ` = **沿 batch 维（= 窗口/状态维）的均值**。`rollout.actions` 的形状是 `(H, B, 29)`，所以 `mean(dim=1)` 确实是"跨状态"的。
- `HA_AT_CENTER=1` 时减掉 batch 均值 ⇒ **常量偏置在损失里不再有任何收益**（c1 打开，v13 没有这个字段）。

### 4.2 奖励口径（**唯一实现**：`diff_vla_wbc/reward_cfg.py` + `isaac_joint.py::reward`）

四个臂完全相同（已逐项对齐 `args.json`）：

| 字段 | 值 | 说明 |
|---|---|---|
| `reward_mode` | `huber_err` | 对**误差距离** `d=√e` 做 Huber，远端线性 |
| `huber_delta` | 0.02 | 平方误差的 δ（m²） |
| `huber_cap` | 0.15 | 仅 `saturating` 分支用；`huber_err` 不用 |
| `reward_delta_pos` | **0.05** | `d` 的 Huber δ（5 cm 内二次、之外线性） |
| `reward_delta_ori` | 0.05 | 同上（弧度） |
| `reward_delta_vel` | 0.05 | 速度项 δ |
| **`reward_d_max`** | **0.30** | **死区**：`d` 先 `clamp(max=0.3)` ⇒ **超过 30 cm 梯度恒为 0** |
| `reward_vel_scale` | **1.0** | 速度项开启（四项全部开启） |
| `root_ori_mode` | `split_huber` | |
| `tail_weight` / `yaw_hinge_lambda` | 2.0 / 0.3 | |
| `term_off` | True | 关掉 soft termination（survival ≡ 1） |

> **死区的设计理由（代码注释原文）**：
> "VLA 的状态里**没有 root 位置**（state46 = 29 关节 + 14 手 + 3 维重力），所以大范围的位置漂移它根本看不见，硬用'贴参考'的梯度把它拉回来等于让它拟合噪声。小漂移（姿态级，0.01–0.05 rad）该拉，大漂移（root 平移 >10–30 cm）不该硬拉 —— 那就是这条死区。"
>
> ⇒ 死区不是随手加的，它是**"状态里没有位置"这个病的补丁**。这一点在 §6-P4/§7 的根因链里是关键。

### 4.3 起点与 burn-in

- `--start-source recorded` + `--start-max-drift 0.05`（保留 61.9% 行、起点漂移 p50 **2.38 cm**）+ **10 步 burn-in**（无梯度）。
- ⚠ 部署起点漂移 ≈ 0，而训练起点 p50 = 2.38 cm ⇒ "零漂移起点"这一角没覆盖（c1 用零漂移的 `ha_transitions.pt` 补上了这一角，但**大偏差那一角仍然没覆盖**）。

### 4.4 梯度路径

- `--fm-grad-backend pathwise`：梯度穿过 4 步流匹配采样（`fm_steps=4`）、穿过 codec 解码、穿过 WM 的 20 步 rollout，回到 LoRA 参数。
- WM 冻结；WBC 冻结；只有 LoRA（rank 32）+ `state_extra`（若启用）可训。
- 3 卡 DDP，24 窗/更新（每卡 8），`--clip-head 10.0`；实测 `s_per_step ≈ 7.0–7.6 s`（c1，200 步共 1442 s）。

### 4.5 部署侧动作链（与训练的一致性）

```
观测(state46/64 + 单帧图像) → VLA 头 → 40 帧 × 78 维 codec 动作 → 取前 64 维 = motion token (40×64)
    → SONIC decoder(token, obs994) → 29 维动作 → q_target = SONIC_DEFAULT_POS + a×scale → PD
```

- **已修的两处口径 bug（都有 bit 级验证）**：
  1. **动作序**：`SonicExecutor.act` 返回 STANDARD 序，而 WM 是 SONIC 序训的 ⇒ 微调时 WM 收到**整体置换**的动作。修复后等价性 `max|Δ| = 0.000e+00`；未修时奖励从 **+0.0173 翻成 −0.0584（−438%）**。
  2. **动作单位**：MDP 的 `action_rate` 用 HA 口径，而动作是 SONIC 单位。换算后与真实弧度差 **2.4e-7**（不换算 **131%**）。实测 `action_rate = 0.0` ⇒ 实际零影响。
- **仍未证实可疑**：`probe_ft_direction` 的状态装配自检出现**单步关节误差 0.483 rad**（位置 0.66 cm），见 §5.4。

### 5.3 落地探针：同状态配对，看 FT 到底改了多少动作

方法（`scripts/probe_ft_landing.py`）：从 `runs/closedloop_r3/base_s0` 的 dump 取 **24 个请求（均匀覆盖 0–20 s，走/站都有）× 3 个噪声种子**，把同一条 `(图像, state64, obs994)` 分别喂 base 头 / FT 头，**同一噪声种子**采样，取前 20 帧平均动作之差 `Δa`，再过**部署同一个 ONNX decoder**。

| 臂 | ‖Δa‖ | /η(0.15) | 逐关节 RMS | 配对噪声内 sd | 效应/噪声 |
|---|---:|---:|---:|---:|---:|
| v10 | 0.398 | **2.65×** | 0.074 | 0.048 | 1.19 |
| v11 | 0.225 | 1.50× | 0.042 | 0.018 | 1.45 |
| v13 | 0.132 | 0.88× | 0.025 | 0.011 | 1.44 |
| c1 | **0.0527** | **0.35×** | 0.0098 | 0.0058 | 1.69 |

跨臂方向：`cos(v10,v11)=0.980`、`cos(v10,v13)=0.985`、`cos(v11,v13)=0.993`、`cos(c1,v13)=0.694`。

**残差结构（本文最重要的一张表）**：把 24 个请求的 `Δa` 减去它自己的均值，看"逐状态那部分"有多大：

| 臂 | ‖mean Δa‖ | 逐请求残差 RMS | **残差/均值** | cos(Δa_i, mean) 中位 | 走半 vs 站半 cos |
|---|---:|---:|---:|---:|---:|
| v13 | 0.1321 | 0.0133 | **0.101** | 0.983 | 0.962 |
| c1 | 0.0527 | 0.0069 | **0.130** | 0.953 | 0.929 |

> **读法**：两个臂的动作改变 **87–90% 是一个常向量**；把 24 个请求分成"前半（在走）"和"后半（站住）"，两半的 Δa 方向余弦仍是 **0.93 / 0.96**。也就是说：**不管状态是走还是站，FT 给的修正几乎是同一个方向。**
> ⚠ 但"常向量"本身不等于"错"——见 §6-P3 与 §10-U1：要判"错"，必须先有**同一批状态上目标自己的残差**，而那个数现在不可信。

### 5.4 方向探针：**工具本身没通过对照，结论不可用**

方法（`scripts/probe_ft_direction.py`）：在同一批状态上算 `cos(Δa, ĝ_WM)`。

| 臂 | cos 均值 | 中位 | >0 占比 | **反序对照** `cos(Δa, reverse(ĝ))` |
|---|---:|---:|---:|---:|
| v13 | 0.160 | 0.154 | 92% | **0.222** |
| c1 | 0.159 | 0.156 | 92% | **0.215** |

- **反序对照反而更高** ⇒ 这个 `ĝ` 估计**区分不出关节序**，不能拿它判"压力有没有落到正确方向"。

| 装配 | 单步位置误差 | 单步关节误差 |
|---|---:|---:|

### 5.5 真物理方向验收（P2，v13）

设置：48 个真实窗口、`δ=0.15` SONIC 单位（≈3.3°/关节）、同一状态、两串动作各在 Isaac 里滚 20 步、比"相对参考的位置漂移"。

| 方向 | WM 的判断 | 真物理同号率 | 真物理漂移变化 |
|---|---|---:|---:|
| **∂J_WM/∂a（WM 梯度）** | + | **33/48 = 69%** ✅ | **−1.23 cm（变好）** |
| v13 实际造成的动作位移 | +（ΔJ=+0.0056） | **20/48 = 42%** ❌ | −0.11 cm（中位 −0.16） |
| 参照：WM 的 20 步保真误差 | — | — | 0.89 cm |

**结论链**：
1. **WM 没训错**：它的 20 步方向在真机上 69% 有效、漂移 −1.23 cm。
2. **奖励也没错**：单步差分增益比 0.90–1.00、方向余弦 0.97–0.98、留出泛化比 1.72。
3. **错在"方向落实"**：策略实现出来的动作变化和 ĝ 的 cos 只有 0.16。
4. **信号强度**：可行改善 1.23 cm vs WM 自身误差 0.89 cm ⇒ **SNR ≈ 1.4**；`ΔJ = +0.0056` 只占 `J = 0.4857` 的 **1.2%**。

## 6. 问题清单（每条：现象 → 证据/指标 → 影响 → 现状）

> 编号 P0–P9，按"对结论的杀伤力"排序。P0/P1 是设计层，P2–P5 是实现层，P6–P9 是度量层。

### P0（设计层，最该先补）：**收缩增益从未被测量，也没被当成指标**

- 现象：四个臂的验收用的是"20 步漂移的绝对值"和"真物理同号率"，**没有任何一处报 `e_end/e_start`**。
- 证据：`scripts/probe_wm_gradient_truth.py` 报的是"漂移变化（cm）"；`scripts/dir_accept_score.py` 报的是"plus/minus 末步距离"；四个臂的 `eval_curve.jsonl` 只有 `imag_return`。
- 影响：**我们无法判断"这条路从来没收缩过"还是"收缩了但被别的东西抹掉"**。这是本文最需要补的一个数。
- 现状：可用现有 dump 直接算（每个 20 步窗口，按偏差区间分组），**不需要 GPU、不需要 Isaac**。

### P1（设计层）：**起点分布和失败分布不重叠（0–2.4 cm vs 25 cm）**

- 现象：v10/v11/v13 起点漂移 p50 **2.38 cm**（`--start-max-drift 0.05`，cap **5 cm**）；c1 是零漂移录制状态。而部署失败发生在 **25 cm**、并且是**已经站住**的状态。
- 证据：§3.2、§5.7（25 cm 来自 `phase2k` 的 `pos_err`）、§5.1（base 在 0–10 s 的 `d_path p50` 只有 3 mm）。
- 影响：
  1. 训练窗口里"本来就没多少可改的"（base 已经贴到 3 mm）⇒ 可学信号只有 **1.2%–5.7%**（§5.2）；
  2. **大偏差（10–30 cm）从来没进入过训练** ⇒ 策略没学过"落后了怎么追"。
- 现状：dump 里已有 8+3 个 seed、1 万多条真实偏差状态（含 `obs994`），**数据现成，只是 loader 没读**。

### P2（实现层）：**落地 Δa 是近常向量，没有逐状态选择性**

- 现象：残差/均值 **0.101（v13）/ 0.130（c1）**，cos(Δa_i, mean) **0.983 / 0.953**，走半 vs 站半 cos **0.962 / 0.929**。
- 证据：§5.3 表；`scripts/probe_ft_landing.py` + `runs/_landing_delta.npz`（24 请求 × 3 噪声，同噪声配对）。
- 影响：即便 20 步想象回报涨了，真机上也只是"整体推了一下"，不是一个"朝减小误差方向"的修正（cos(Δa, ĝ) = 0.16，§5.4）。
- 现状：**已确认是"输出的事实"**，但"它是不是错的"仍缺一个前提（§10-U1）。

### P3（实现层）：**训练侧的选择性指标与落地指标不是同一个量，且损失停在"残差≈0"**

- 现象：c1 日志 `pred_resid_ratio ≈ 2.3`（头在跨状态变），但 `loss/action_target ≈ 0.0205` ≈ `tgt_resid_norm²` = 0.139² = **0.0193**。代入 `0.0205 = 0.035² + 0.139² − 2·cov` ⇒ **cov ≈ 0、corr ≈ 0**。
- 证据：`logs/joint_c1.log`；`diff_vla_wbc/v3_step.py:877-899`（`mean(dim=1)` = batch 维，已核实 `Rollout.actions` 是 `(H,B,29)`）。
- 影响：
  1. **`pred_resid_ratio` 不能用来证明"头有选择性"**——它是 20 步**想象 rollout** 上的跨 batch 统计，t>0 时不同窗口已经在不同状态上，包含轨迹分叉；
  2. 但 `loss = tgt_resid²` 说明**预测的逐状态残差≈0 且与目标零相关** ⇒ 中心化（`HA_AT_CENTER=1`）之后，逐状态那一半仍然没学进去。
- 现状：**这是目前对"为什么常向量"最硬的一条证据**；机制解释见 P4。

### P4（实现层）：**动作目标的 t>6 步口径不成立（代码注释自己写了）**

- 现象：`A_tgt[t]` 是在 **base rollout 的状态**上算的，`rollout.actions[t]` 在**当前策略的状态**上；`--action-target-steps` 实际是 **20 = 整个视界**。
- 证据：`v3_step.py:866-870` 注释原文："只用**前 k 步**：base 与当前策略的想象轨迹从第 6 步起会分叉，那时 A_tgt[t] 在哪个状态上与 rollout.actions[t] 不再是同一个状态。前几步状态重合，回归目标才严格有意义。"
- 影响：损失对 t>6 的项**结构上不可能降到 0**；梯度被"轨迹分叉"污染，而不是"动作方向"。这与 P3 的 corr≈0 一致。
- 现状：**一行参数就能修**（`--action-target-steps 20 → 1..5`），还没跑。

### P5（实现层）：**奖励死区 30 cm；它在"从站住状态起训"时立刻咬人**

- 现象：`reward_d_max = 0.30`，`_huber_on_error` 先 `d.clamp(max=0.3)` 再算 Huber ⇒ **30 cm 外梯度恒为 0**。
- 证据：`diff_vla_wbc/isaac_joint.py:73-105`（docstring 明写"超过死区后惩罚恒为常数、梯度为 0"）；`runs/joint_c1/args.json` 的 `reward_d_max=0.3`。
- 影响（**必须分两种情况说**）：
  1. **当前训练完全碰不到死区**：起点 2.4 cm + 20 步最多 12 cm = 上限 ~14 cm < 30 cm ⇒ **死区不是四个臂失败的原因**（这一条我曾在上一轮口头里说错，已修正）；
  2. **但如果按 P1 的建议"从 25 cm 起训"**：25 cm 起，参考走 8 步就过 30 cm，**20 步里后 12 步梯度为 0** ⇒ 必须先放开死区，否则换了起点也学不到"追上去"。
- 现状：死区是**"没有位置"这个病的补丁**（§4.2 注释），所以正确顺序是"先补位置 → 再放死区"。

### P6（度量层）：**方向探针无效（反序对照 > 真序）**

- 现象：真序 `cos = 0.160`，反序对照 `0.222`；状态自检单步**关节误差 0.483 rad**。
- 证据：§5.4。
- 影响：**"方向没落实"这个结论目前只有 42% 同号率（§5.5）支撑，没有可用的 `cos(Δa, ĝ)` 支撑**；`§3.6c` 的"判据 cos ≥ 0.5 且 残差/均值 ≥ 1.0"现在两个数都不可信。
- 现状：要先修关节口径，才能用这条路做判据。

### P7（度量层）：**任务层完全不可观测**

- 现象：闭环奖励恒 0（3099/3099 条）、`steps.jsonl` 不记物体、WM 输入/输出没有手也没有物体（`133 = 71 + 29 + 33`，29 维动作无手指）。
- 证据：§5.9、§2。
- 影响：
  1. "成功率 0/8"无法归因（没走到 vs 抓空）；
  2. **WM 奖励在结构上看不见抓取**——它最多优化"身体跟随"，既不能奖励"抓住"也不能惩罚"抓空"；
  3. 任何"压漂移"的结论都只是代理指标，和任务成功只有"必要不充分"的关系。
- 现状：要做 N0（手↔物体最小距离、物体抬升、手指闭合）必须先加字段。

### P8（度量层）：**`--sample-avg` 这类"降采样噪声"的技巧对站桩吸收态是反作用**

- 现象：8 对配对 4/8、均值 +11.75 cm、方差 2.45×；`sa4_s4` 只走 0.02 m。
- 证据：§5.8。
- 影响：任何"取平均降噪"的推理技巧都会把输出推向条件均值 = "站"。**判据里必须加"冻结点是否提前"**（`scripts/analyze_closedloop_stall.py` 直接给这一列）。
- 现状：已判负，不再投入。

### P10（范围层）：**训练是多任务，验收只有一个任务**

- 现象：A' / WM / FT 起点集合都是 **6–7 个任务全量**（§3.1），但所有闭环验收（8 对配对、方向验收、站桩分析）**只在 DoubleDesk 上**做。
- 证据：`runs/isaac_motion/ha_cmd/packed.pt` 699 clips / 7 任务；`configs/ha_closedloop_pin.json` 里其实已经 pin 了 **7 个任务**（DoubleDesk / PPBox / Boxing / OpenDoor / SitSofa / VisionNavi / Football-Single）；`scripts/ha_isaac_closedloop.sh` 用 `TASK=<别名>` 就能切换。
- 影响：
  1. "联合微调没有正收益"这个结论**只对 DoubleDesk 成立**，不能推广；
  2. 反过来，**多任务 + 无相位**会让"逐状态目标"更难辨识——batch 里混着 7 种完全不同的运动（VisionNavi 走 4.9 m vs Boxing 1.55 m），条件均值被抹得更平。这可能是 §5.3 那个常向量的一部分原因。
- 现状：换任务的开关是现成的（`TASK=Boxing bash scripts/ha_isaac_closedloop.sh`），**没有做过任何一次非 DoubleDesk 的闭环**。

### P9（流程层）：欠采样/自指两类坑已复发过一次

- `--sample-avg` 在 4 对上"4/4 全涨"，补到 8 对变 6/8 且均值为负 ⇒ **默认 8 对 + 符号检验**（`scripts/judge_paired_closedloop.py`）。
- P1 v1 的"目标自指"使损失恒等于 η²、梯度为 0（日志里 `loss/action_target` 钉在 0.0225 = 0.15²）⇒ **锚点必须用 base 动作，且跑 2 步冒烟看损失是否在变**。

## 7. 根因链（一张图）

```
state 里没有位置/相位（state46 = 29 关节 + 14 手 + 3 重力；图像只有一帧）
│
├─(A) 大偏差对策略不可观测
│      └─► 奖励加 30 cm 死区（"大漂移不该硬拉"）
│             ├─ 当前训练：永远碰不到（起点 2.4 cm）
│             └─ 若从 25 cm 起训：20 步里后 12 步梯度 = 0  ← 必须先放开
│
├─(B) "站/走"只能靠姿态代理
│      └─► 站桩后 token 输出"站"（0.011–0.047 m/s）
│             └─► 动作层残差（Δa 0.13）改不动命令（"站→走"差 ≈0.22 m/s 当量）
│                    └─► 真值 token 回放也只到 0.85–1.13 m（§5.7）← 瓶颈在命令下游
│
└─(C) 逐状态目标不可辨识
       └─► 回归最优解 = 全局平均方向
              └─► 落地 Δa 常向量（cos 0.95、残差/均值 0.13）
                     └─► 20 步想象收益（1.2–5.7%）转不到真机

并行还有两个"放大器"：
  · 起点 0–2.4 cm ⇒ 窗口里本来就没多少可改（base 已贴到 3 mm、可学信号 ~1%）
  · WM 20 步误差 0.89 cm vs 可行改善 1.23 cm ⇒ SNR 1.4（信号和模型误差同量级）
```

**一句话**：不是"WM 不好"或"联合微调写错了"，而是**我们在一个"几乎已经最优"的起点分布上，用一个 SNR≈1.4 的、并且把常量偏置显式扣掉的损失，去学一个输入里分辨不出来的逐状态修正；然后在偏差 25 cm、命令说"站"的分布上去验收。**

## 8. 可能的改法（按成本排序，每条带判据）

> 原则：**先诊断、再改输入、最后改训练**。改训练超参（λ_r / trust / 步数）已经被四个臂证明无效，不再列。

### F0-A（~40 min，1 GPU，不用训练）GT 动作回放：把"执行链"和"命令"分开

把录制的 decoder 动作**直接**喂给执行器（绕过 token 和 VLA），滚 40 s。
- 判据：能到 **≥1.8 m** ⇒ 执行链没问题，缺口 100% 在命令侧；仍停 **≤1.2 m** ⇒ 执行链/WBC/场景是硬瓶颈，**整条 WM+FT 线对任务成功无效**。

### F0-B（~10 min，1 GPU）重启单元测试：从站住状态喂"走"的 token

从 dump 的站住状态起，喂 5 s 参考 25–30 s 的真值走路 token，看它动不动。
- 判据：位移 **≥0.2 m** ⇒ 能重启（命令问题）；**≤0.05 m** ⇒ 不能重启（执行链/物理卡住）。

### F0-C（~1 h，1 GPU+Isaac）WM 在失败状态上的有效性

从 dump 的站住状态起，用 Isaac 做真值，测 WM 的 **20 / 50 / 100 步**位置与关节误差。
- 判据：100 步位置误差 **<2 cm** ⇒ 长视界可用；**>5 cm** ⇒ 这个 WM 只能当局部模型，必须先在 25 cm 状态上采数据。
- 顺带验证 §5.4 那个 **0.483 rad** 是不是口径 bug。

### F1（设计层，优先级最高）**给 state 加位置/相位**

`state_extra` 的 46→52 通道已就位（`diff_vla_wbc/state_extra.py`，`--state-extra` 现有 `none/rotlocal6/abs6/vel6/ori6`），加 3–6 维：
`[t/T, 沿参考弧长进度, heading 系位移(2), 低频 q̇(2)]`（先做 3 维即可）。
- 理由：它是 (A)(B)(C) 三条根因的**共同前提**；有了它，"大偏差"才可观测，死区原来的理由才消失，逐状态目标才可辨识。
- 判据：同一批 24 个状态上，`Δa` 的**残差/均值从 0.13 提到 >0.5**；并且 2×2 置换里"状态"通道单独就能把输出从"站"翻成"走"。

### F2（依赖 F1）放开奖励死区

`reward_d_max 0.3 → 1.0`（或改 log 形状）。
- 判据：从 25 cm 起、20 步 rollout 里 **每一步的 `huber_err_root` 梯度非零**（打印验证），且"站着"与"追上去"的奖励差 > 5×。

### F3（依赖 F1）起点换成 dump 里的真实偏差

`runs/closedloop_r3/*/dump/steps.jsonl`（8+3 seed，1 万+ 条，含 `obs994`），按偏差分桶采样。
- 判据：训练窗口覆盖 **0–5 / 5–15 / 15–30 cm** 三档；每档 `n ≥ 8`。

### F4（一行参数）修动作目标的口径

`--action-target-steps 20 → 1..5`（修 P4）。
- 判据：`loss/action_target` 明显低于 `tgt_resid_norm²`（现在是相等），并且 `corr(pred_resid, tgt_resid)` > 0.3。

### F5（依赖 F0 的结论）提高"杠杆"

如果 F0-A 说执行链能跟，那么问题在命令，动作残差（0.13）天生改不动命令（0.22 m/s 当量）。可选：
- **token 空间残差**（在 64 维 token 上加 Δ，而不是在 29 维动作上加）；
- 或直接做**相位条件**（N2），让命令不再输出"站"。
- 判据：命令速度当量从 0.03 提到 **≥0.15 m/s**（用 `probe_vla_input_factorial.py` 的检索法测）。

### F6（工具修复）修 `ĝ` 探针的关节口径

把单步关节误差从 **0.483 rad** 降下来（先查 q/qd 的 STANDARD vs SONIC 序、以及零位）。
- 判据：**反序对照 cos 明显低于真序**（例如 ≤0.5×），否则这条路不能用于任何判据。

### F7（任务层）让"抓没抓住"可测

`steps.jsonl` 加：手↔锤子最小距离、锤子高度/位移、手指闭合度；并修闭环奖励恒 0 的 harness。
- 判据：能对每个 seed 输出 `min(hand-object)` 和 `object_lift`；否则"0/8"永远无法归因。

### F8（明确不做）

- `--sample-avg`（含 8）：已判负（§5.8）。
- LoRA rank 32→128：容量不是瓶颈（2×2 置换里同一网络能输出 0.25 m/s 的"走"）。
- P3 动作残差适配器：改部署侧管线、风险面大，且和 F5 重复。
- 只跑单 seed / 只跑 4 对：欠采样已骗过我们一次（§5.8、P9）。

## 9. 给 reviewer（GPT）的具体问题

1. **§1.4 的"局部收缩"判据对吗？** 用 `e_end/e_start` 够不够？是否需要看误差的**谱半径/李雅普诺夫函数**，或者"每窗位移能力上限 12 cm"这个约束有没有被低估（例如参考会往回走、heading 会变）？
